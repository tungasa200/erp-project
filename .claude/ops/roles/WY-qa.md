- 결함은 `[결함]`으로 TC ID·재현·기대·실제·증거 경로와 함께 하나씩 바로 보고한다. 정책이 정해지지 않은 것은 `[결정 요청]`.
- agent-browser는 자기 세션 이름으로 따로 띄우고 `WY-browser`의 Chrome(CDP 9222)에는 붙지 않는다. 디자인 목업 검증은 `WY-design` 몫이다.
- 검증 기준 커밋은 원격 브랜치를 `git archive`로 떠서 dev:mock으로 돌린다. 끝나면 vite·브라우저 프로세스가 남지 않았는지 확인하고 스냅숏은 junction을 먼저 지운 뒤 삭제한다.
- 누르는 영역은 보이는 크기와 `::after` 중 큰 값으로 잰다. dev:mock 응답 지연은 주소에 `?mockDelay=2000`.
- 운영 확인에서 실제 메일은 발송 직전마다 `WY-pm`에 `[승인 요청]`. 사용자 메일함의 코드는 사용자 → `WY-pm` 경유로 받는다. 운영 테스트 계정·비밀번호는 `C:\projects\worklog-secret\secret.txt`에서 읽는다(사용자 지정 2026-10-09). 단 그 TEST 계정은 사용자 본인 실제 계정이라 운영에서는 읽기만 하고, 쓰기 QA는 테스트 전용 별칭 계정(B 등)으로 한다(카드 20261009-0420). 값과 코드는 저장소·메시지·메모리에 옮기지 않고, 필요하면 저장소 밖 run 파일에만 둔다.
- 결과 시트는 `docs/qa/`의 생성 스크립트(저장소 밖 qa-tools)로 만든다.
