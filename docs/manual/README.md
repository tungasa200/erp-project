# 사용자 매뉴얼 원고 (docs/manual)

WY Worklog 사용 설명서(PDF)의 원고·이미지·생성물을 둔다. 계획 [../매뉴얼_작업계획_v1.md](../매뉴얼_작업계획_v1.md), 결정 D-214·D-215·D-216.

## 규칙

- 화면 기준은 업무일지 숨김(D-214·D-215) 뒤의 운영 화면이다. 업무일지·내보내기·회사 양식·프로필 탭·미인증 안내는 쓰지 않는다. 하루 마감은 '일지' 말이 빠진 모양으로 쓴다(문안 docs/ux/업무일지숨김_문안_v1.md).
- 낱말은 앱 화면에 나오는 말을 그대로 쓴다. 용어 정의는 [03-용어.md](03-용어.md)를 기준으로 하고, 다르게 쓰고 싶으면 WY-planner에 먼저 말한다.
- 예시는 아래 '가상 데이터'의 이름만 쓴다. 실제 기업명·프로젝트명·사람 이름을 쓰지 않는다.
- 근거 ID(요구사항·화면·결정)는 본문에 쓰지 않고 장 머리의 HTML 주석 `<!-- 근거: … -->`에 적는다.
- 이미지는 `images/<장 번호>/<화면 ID>_<W|M>[_<상태>].png`. W = 웹 1280px, M = 모바일 390px. 본문에는 `![설명](images/04/SCR-HOME-01_W.png)`처럼 넣고, 아직 안 찍은 그림도 같은 경로로 미리 적어 둔다(촬영 WY-qa).
- 이미지 커밋 조건(D-216 ②, D-207의 매뉴얼 예외): 매뉴얼 계정의 가상 데이터일 것, 계정 메일 등 개인 정보 칸은 가리거나 화면에 없을 것. 못 지킨 이미지는 커밋하지 않는다.
- 문장은 짧게, 해요체. 한 단계 = 한 문장 + 필요하면 그림 하나.

## 가상 데이터 (매뉴얼 계정)

- 회사: 가나다상사(가상 회사 — 2026-10-12 웹 검색으로 같은 이름의 회사가 나오지 않음을 확인). 사용자는 마케팅팀 대리 김우연(가상 이름, 계정은 D-217), 근무 월~금 09~18시.
- 프로젝트: **행사 / 설문 / 팀운영** (계정에 넣는 이름 그대로. 공백이 없어야 빠른 입력 `@행사`처럼 쓸 수 있어요). 무엇의 프로젝트인지 풀어 쓸 때만 '봄 신제품 소개 행사'·'분기 고객 설문'·'팀 운영'이라고 설명하고, 프로젝트 이름 자리(칩·`@`·목록)에는 짧은 이름만 쓴다.
- 태그: #보고 #회의 #디자인 #예산 #외부.
- 반복 일정: 매주 월 09:30 팀 회의, 매일 17:30 메일 정리. 업무 없는 일정 예: 외부 협력사 미팅.
- 업무 예시: 행사장 견적 비교, 초대장 시안 검토, 설문 문항 초안, 주간 보고 정리, 예산안 수정. 실제 입력 목록은 WY-qa가 계정에 넣으며 정한다.

## 생성

PDF 생성 스크립트(Markdown → HTML 인쇄 CSS, Pretendard → headless Chrome)는 WY-planner가 docs/tools 쪽에 만든다. 발행한 PDF는 frontend/public/manual/에 고정 이름으로 복사해 랜딩·앱에서 연다(링크 위치는 docs/개정대기.md).
