## 1. 요약

### 가장 큰 문제 5개 (영향 순, COM-01·02 제외)
1. **UX-HOME-01 홈 위계가 주 작업과 반대다(재확인, 중간).** critique에서 인지 부하 체크 2개(단일 초점·시각 위계)가 실패했다. frontend-design 기준으로도 "큰 숫자 + 작은 라벨 + 강조 타일"이라는 기본 템플릿 처리다. 하루 10번 한 줄 적으러 여는 화면이 대시보드로 시작한다.
2. **UX-MOB-01 모바일 시트에 누를 수 있는 저장 버튼이 없다(신규, 중간).** 저장 수단은 "Enter 저장" 글자와 N 배지뿐이고, `enterKeyHint`도 없다. 모바일 빠른 기록의 주 경로다.
3. **UX-COM-03 팔레트 Enter가 찾기 대신 추가한다(구분 변경: 구현 → 의도, 중간).** 소스 주석(CommandPalette.tsx:183)이 "결과가 있어도 '업무로 추가'를 맨 앞에"라고 의도를 밝힌다. 화면정의서와 코드 중 어느 쪽을 고칠지 WY-design 결정이 필요하다.
4. **UX-COM-25 상태 메시지가 낭독기로 전해지지 않는다(신규, 중간).** 빠른 입력 해석 결과·"시간으로 읽지 못했어요" 경고, 팔레트 결과 수·오류, 타이머 정지 뒤 메시지가 해당한다(WCAG 4.1.3).
5. **UX-COM-22·23·24 모바일 하단 셸의 기본기(신규, 중간).**
   - COM-22: `viewport-fit=cover`인데 하단 탭·타이머 띠·토스트에 안전 영역(safe-area) 여백이 없다.
   - COM-23: 어두운 토스트 위 포커스 링 대비가 2.39:1이다.
   - COM-24: 하단 탭이 포커스된 요소를 가릴 수 있다(scroll-padding 없음).

### 잘된 점 3개 (유지할 것)
1. **빠른 입력 해석 피드백.** critique에서 "제품에서 가장 좋은 순간"으로 꼽혔다. "~금"이 "마감 10/16(금)"으로 바뀌고, 미리보기 문구가 결과를 알려 준다. 한글 조사 계산(particle.ts)과 IME 조합 중 Enter 막기도 있다.
2. **절제된 모션.** emil 점검에서 기준을 어긴 모션이 하나도 없었다. 애니메이션 3개는 모두 상태·로딩용이고 움직임 줄이기에 대응한다. `transition: all`·scale(0)·ease-in·300ms 넘는 UI 모션도 0이다. 팔레트처럼 키보드로 여는 것에는 모션이 없다(emil 원칙과 같음).
3. **접근성 바탕.** 전역 `:focus-visible` 링이 있고 `outline:none`을 대체 없이 쓴 곳이 없다. 아이콘 버튼은 모두 aria-label이 있다. 토스트는 상시 live 영역이고 마우스·포커스가 올라가면 멈춘다. 팔레트를 닫으면 포커스가 원래 자리로 돌아간다. 시트에는 Tab 가두기, Esc, 포커스 복귀가 있다.

## 4. critique B: detector·브라우저 증거
운영 주소, TEST_B 계정, agent-browser 세션 `WY-ux-critB`에서 했다. 데이터는 만들지 않았다. CLI detect는 리드 결정으로 건너뛰었다.

- **방법.** `impeccable live-server`의 detect.js를 `<script src=localhost>`로 넣으면 막혔다. https 공개 사이트에서 루프백 자원을 부르는 것을 Chrome의 로컬 네트워크 접근 규칙이 막는 것으로 보인다. 그래서 같은 번들(WASM 포함)을 받아 페이지 안에서 직접 실행했다(`impeccableDetectAsync`). 계산값도 페이지에서 함께 쟀다.
- **detector 결과:**
  - 홈 1280: 1건. 홈 390: 1건. 빠른 기록 시트 390: 2건. 팔레트 1280: 1건. 404: 0건.
  - 실제 문제는 하나다. placeholder 대비가 3.2:1이다(#8a8fa3 on #fff, WCAG 1.4.3 기준 4.5:1에 못 미침). 홈 입력과 시트 입력이 같은 클래스라 토큰 하나를 고치면 둘 다 해결된다.
  - 시트 placeholder는 예시 문법(`14-16 … @영업`)을 알려 주는 문장이라 무게가 더 크다. 시트·팔레트 화면에서 다시 잡힌 홈 placeholder는 뒤에 깔린 같은 요소라 중복이다.
  - 팔레트 placeholder는 잡히지 않았다.
- **보조 계산값:**
  - 글자 크기: 홈 1280에서 12종(10·10.5·11.5·12·12.5·13·14·15·16·17·28·34px), 390에서 11종.
  - 모서리 반경: 1280에서 14종. 이 수치로 X-01(토큰 단계)을 뒷받침한다.
  - 390에서 홈 빠른 입력 글자가 15px다. 16px 미만이라 iOS Safari에서 포커스할 때 화면이 확대된다(실기기 필요). 시트·팔레트 입력은 16px 이상이라 괜찮다.
  - 390에서 빠른 입력의 실제 입력 높이는 25px다. 보이는 필드는 52px이지만 감싼 div가 탭을 넘기지 않아서, 위·아래 가장자리를 누르면 포커스가 안 될 수 있다(실기기 필요).
  - 하단 탭, `N`·`?`, 세그먼트 버튼은 390에서 44px 이상이다. 1280의 36px 세그먼트는 포인터 환경이라 지적하지 않는다.
- **v1.1 반영:** 신규 COM-33(중간)과 HOME-13(낮음) 두 건으로 본다. §6에는 올리지 않았다. 통합 v1.1에서 COM-33은 같은 토큰인 COM-09에 합쳤고, HOME-13의 15px 부분은 COM-10에 합쳤다. HOME-13에는 입력 높이 25px 문제만 남겼다.
  - COM-33: placeholder 대비 3.2:1. 시트 예시 문법 포함.
  - HOME-13: 390에서 빠른 입력이 15px이라 iOS에서 확대되고, 입력 높이가 25px다.

### X-04 Esc·되돌리기 규칙 (COM-01, v1 측정값만 씀)
- 쟁점: 빠른 입력에서 Esc가 무엇을 하는가. 앱 전체 되돌리기를 어떻게 일관되게 할지.
- 측정(v1)
  - 홈 빠른 입력: Esc를 누르면 value가 ""이 되고, Ctrl+Z를 눌러도 ""이다.
  - 모바일 시트: Esc를 누르면 초안이 남는다.
  - 저장 직후 Ctrl+Z는 앱 되돌리기로 가지 않는다(COM-02).
  - 화면정의서 SCR-COM-02의 정의는 "Esc로 입력 비우기"다.
- **안 A: Esc는 "닫기·포커스 빼기"만 하고 글은 남긴다(모든 입력 공통).** 비우기는 입력칸의 × 버튼으로 한다.
  - 장점: Linear·Todoist 빠른 추가, Slack 입력창과 같은 기대다. 팝오버를 닫으려던 Esc가 글을 지우지 않는다. 시트와 같아진다.
  - 단점: 키보드로 비우려면 Ctrl+A·Delete 두 번이 필요하다.
- **안 B: Esc를 두 번 눌러야 비운다.** 첫 Esc는 칩 메뉴·도움말을 닫거나 포커스를 빼고, 두 번째 Esc(1초 안)가 비운다. 비운 글은 Ctrl+Z로 돌아온다.
  - 장점: 빨리 비우는 길이 남는다.
  - 단점: 숨은 규칙이고, 습관적으로 두 번 누르는 사용자에게는 같은 손실이 남는다.
- **안 C: 지금처럼 Esc로 비우되, 비우면 "입력을 지웠어요 · 되돌리기" 토스트를 띄운다.**
  - 장점: 화면정의서를 고치지 않아도 된다.
  - 단점: Esc마다 토스트가 떠서 시끄럽다. 토스트를 놓치면 그대로 손실이다.
- 앱 공통 되돌리기 규칙 제안(세 안 공통)
  - 데이터를 바꾸는 동작은 5초 되돌리기 토스트를 띄운다.
  - Ctrl+Z는 포커스가 "글이 있는 입력칸"이 아니면 토스트 되돌리기로 간다.
  - 입력칸이 비어 있으면 앱 되돌리기로 넘긴다.
- 근거: impeccable critique 휴리스틱 3(사용자 통제)·5(오류 예방). web-design-guidelines "되돌릴 수 없는 동작은 확인 또는 되돌리기 창"(Navigation & State). emil 해당 없음.
- **추천: 안 A + 공통 규칙.** 화면정의서 SCR-COM-02의 "Esc로 입력 비우기"를 개정해야 하므로 WY-design 결정이 필요하다.

### X-11 같은 일을 하는 두 길 + 점선의 뜻 (COM-21, COM-12)
- 쟁점 ①: 390 업무 목록에 화면 안 [+]와 하단 탭 +(빠른 기록)가 함께 있다.

  - **추천: 안 B.** 두 안 모두에서 펼치기 버튼은 일반 버튼으로 바꾼다.
- 근거: impeccable critique 휴리스틱 4(일관성). frontend-design "구조 장치(테두리·번호 등)는 장식이 아니라 정보를 담는다".

### X-12 스킬 충돌 ①: 누름 피드백·진입 모션
- 쟁점: emil-design-eng는 모든 버튼에 `:active { scale(0.97) }`을 권하고, 토스트·시트·팝오버에 진입 모션을 권한다. 생산성 도구 원칙(반복 사용·키보드)과 emil 자신의 "키보드 동작은 애니메이션 금지"는 모션을 줄이라고 한다.
- 측정(리드 영역 소스)
  - transition 0개.
  - 애니메이션 3개
    - 시트 rise 180ms ease-out
    - 토스트 카운트다운 5s linear
    - 스켈레톤 1.4s
  - 셋 모두 움직임 줄이기에 대응한다.
  - `:active` 0개다. hover 게이트 `(hover:hover)`는 앱 전체 0개다(ux2 확인).
  - 시트를 80px 미만 끌다 놓으면 즉시 튀어 돌아온다(QuickSheet.tsx).
- **안 A: emil 그대로.**
  - 모든 누르는 요소에 `:active scale(0.97)`, 120~160ms ease-out을 준다.
  - 토스트 진입·퇴장은 transition, 시트·팝오버는 origin-aware 진입, 쌓이는 토스트는 이동 모션을 준다.
  - 장점: 손에 닿는 반응이 생겨 PWA가 앱처럼 느껴진다.
  - 단점: 카드·타일·목록 행처럼 큰 요소가 줄어들면 정보 밀도 높은 화면에서 글자가 떨린다. 하루 수십 번 누르는 행에 모션이 붙는다.
- **안 B: 최소 모션 규칙.**
  - 키보드로 여는 것(팔레트·칩 메뉴·N 단축키·도움말)은 모션을 계속 0으로 둔다.
  - 누름 피드백은 배경 한 단계 어둡게(색)로 하고, scale은 작은 원형 버튼(+, 타이머 버튼)만 쓴다.
  - hover 색은 `(hover:hover) and (pointer:fine)` 안에서만 준다.
  - 토스트·시트는 진입만 opacity+translate 180ms 이하로 하고, 퇴장은 즉시 또는 진입보다 빠르게 한다.
  - 시트를 끌다 놓았을 때 되돌아가는 동작은 200ms drawer 곡선을 쓴다(emil 수치 채택).
  - 장점: emil의 빈도 표("하루 100번 이상은 모션 금지, 수십 번은 줄임")를 그대로 적용한 결과다. 터치에서 hover가 남는 문제도 함께 푼다.
  - 단점: 버튼 반응이 "앱다운" 느낌은 A보다 약하다.
- 근거: emil(빈도 표, 키보드 동작 금지, 퇴장이 진입보다 빠르게, hover 게이트), web-design-guidelines Animation·Touch, impeccable audit Performance(transform·opacity만), AIT-14·21(장식 모션 없음 유지).
- **추천: 안 B.** 두 스킬의 권고가 겉으로는 갈리지만, 빈도 기준을 적용하면 emil 자신의 원칙과도 맞는다.

- 판단 요청: 단계적으로 가려면 B+C 먼저, D는 묶음 3. 리드 추천은 D이고, 이견은 남긴다.

### X-08 통계 게이트 (ux2) — 동의(안 C) + 보완 1건
- 동의: 숫자 카드는 바로, 추이 차트는 7일 뒤. 7일 정책의 취지(추이는 표본이 있어야 의미가 있다)를 지키면서 이미 쌓인 값을 보여 준다.
- **보완:** 7일 미만일 때 기간 버튼은 꺼짐 + 이유(title·보이는 한 줄)로 둔다. "켜진 채 반응 없음"이 가장 나쁘다(critique 휴리스틱 1). "남은 일수"의 기준 날짜를 문구에 쓴다는 ux2 안에 동의한다.
- 홈 연결: 홈 "이번 주 완료" 타일(HOME-02)과 통계 숫자 카드가 같은 값을 다른 이름으로 보이지 않게, 용어를 하나로 정한다(축 5).

### X-07 캘린더 겹침·일 보기 패널 (ux3) — 동의(A + D) + 보완 2건
- 동의: 열 상한 + "+n"은 월 보기 "+n개 더보기"와 같은 규칙이라 배울 것이 없다. D(패널 기본 접기)로 일 보기 열이 122 → 약 400px이 되면 대부분의 날은 상한에 닿지 않는다. 비용 대비 효과가 D가 가장 크므로 D 먼저라는 순서에 동의한다.
- **보완 ①(키보드·낭독기):** "+n" 묶음은 Tab으로 닿는 버튼이어야 하고, 이름은 "14시대 일정 3개 더"로 한다. 팝오버는 열 때 첫 항목에 포커스, Esc로 "+n"에 복귀한다(팔레트·칩 메뉴와 같은 규칙, 이미 앱에 있는 패턴).
- **보완 ②(기본값 기억):** ux2 의견대로 접힘 상태는 사용자별로 기억한다(기기 단위 localStorage로 충분, 서버 설정은 과함). 접힌 막대에는 "업무 n · 기록 n건" 요약을 남긴다(ux2 이음매 반박 수용).
- 주 1280 상한 2(57px 열 → 28px 2개)는 공격적이지만, 주 보기의 목적은 "어디가 바쁜가"이므로 맞다고 본다.

### X-09 메일 프리헤더 (ux3) — 동의(안 A)
- 동의: 인증은 드문 동작이라 속도 이득은 작고, 잠금 화면 노출은 한 번이어도 크다. D-41의 의도와 같다.
- 보완: 텍스트 버전(multipart/alternative의 text/plain) 첫 줄도 코드로 시작하지 않게 한다. 일부 클라이언트는 미리보기를 텍스트 버전에서 뽑는다. ux2가 지적한 공백 채움과 함께 실제 클라이언트 확인이 필요하다(실기기 필요, 실제 발송은 사용자 승인).

### X-10 키 컬러 대비 (ux3) — 동의(A + 링크 accent-ink) + 보완 2건
- 동의: 프리셋 값 조정(A)은 한 파일 수정이고 사용자 색 정체성을 지킨다. 링크를 accent-ink로 바꾸는 것은 한 줄이다.
- **보완 ①(이미 저장한 색):** A만으로는 이미 청록·초록·주황을 저장한 사용자가 계속 미달이다. C(저장 막기)는 D-185를 다시 열어야 하므로 중간안을 제안한다. 저장할 때 on-accent 글자 4.5:1 미만이면 막지 않고 "이 색은 버튼 글자가 흐려 보일 수 있어요"라고 알리고, 프리셋의 조정 값을 함께 제안한다.
- **보완 ②(검사 대상 바탕):** theme.ts의 대비 검사는 바탕·흰색만 본다. 리드 COM-23에서 키 컬러 포커스 링이 토스트 바탕(#1A1C2B) 위에서 2.39:1로 측정됐다. 키 컬러 계약에 "어두운 띠(banner) 위 포커스 링"을 넣거나, 토스트 안 포커스 링을 키 컬러와 분리한다(COM-23 제안). ux2가 말한 accent-soft·통계 막대 3:1 재계산도 같은 계약 표에 넣는다.
- theme-color: ux3의 COM-98 지적은 리드 COM-26과 같다. 통합 때 하나로 묶는다.
- 기본 키 컬러 유지: 동의(제안·취향). 바꾼다면 X-01 토큰 단계와 함께 한 번에 하는 것이 QA 비용이 가장 작다.

## 부록 C. 재반박 (리드 안에 온 반박)

ux2 반박(부록 B)과 ux3 반박(부록 B)을 받았다. 각각 한 번씩 답한다. 판정은 `디자인방향_교차리뷰_v1.1.md`에 있다.

### ux2 반박에 대한 답

- X-01
  - 13.5px의 처리: "반 픽셀은 아래 단계로(13.5 → 13)"라는 ux2 보완을 받아들인다. 표 줄 간격이 지켜진다.
  - 인쇄 서식 제외: 일지 문서 서식(`paper.module.css`)은 내보내기 결과와 같아야 하므로 토큰 단계 밖으로 둔다는 데 동의한다. 다만 화면의 문서 미리보기는 같은 서식을 쓰므로 "서식 전용 단계"를 따로 적어 둔다.
- X-02
  - accent-soft 조건: "글자 4.5:1 + 경계 3:1"을 규칙에 넣는다.
  - 동작이 둘 이상인 행: "accent-soft + 윤곽 조합"을 규칙에 넣는다. 확인 대기 3동작 행은 행 전체 클릭으로 대신할 수 없다는 반박이 맞다.
- X-04
  - Ctrl+Z 모호함 반박을 받아들인다. 규칙을 "되돌리기의 기준은 보이는 [되돌리기] 버튼이고, Ctrl+Z는 토스트가 떠 있으면서 포커스가 글 입력칸이 아닐 때만 연결한다"로 고친다. 홈 빠른 입력(COM-02)도 "저장 직후 입력칸이 비어 있으면 글 입력칸이 아니다"로 본다(빈 칸은 되돌릴 글이 없음).
  - 확정 되돌리기는 ux2 안 D를 지지한다(X-05).
- X-11: 필터 중 [+] 규칙(필터에서 보이지 않을 업무면 안내하거나 끄기)을 안 B 조건에 더한다.
- X-12: 순서를 "hover 게이트 먼저, 누름 색은 그다음"으로 고친다. 일지 표 행처럼 hover 바탕이 있는 곳은 게이트 없이 누름 색을 더하면 구분이 안 된다는 반박이 맞다.
- X-13: placeholder 규칙을 셋으로 나눈다. "예시 패턴이 있으면 '예: …', 지시문이면 문장 그대로, 끝 '…'는 붙이지 않는다". 인쇄 서식 날짜는 공용 함수 출력과 같아야 한다는 보완도 받아들인다.

### ux3 반박에 대한 답

- X-01 캘린더 블록 단계: **받아들인다. 다만 범위를 좁힌다.**
  - 11px를 "밀집 단계"(`--text-dense`)로 두고, 시간 그리드 블록 안에서만 쓴다. 블록 높이가 32px 미만이면 12 한 줄, 블록 안 보조 글자(시간·장소)는 11이다.
  - 앱 화면의 칩 11.5px(ux2 LOG-57 세 곳)는 11이 아니라 12로 올린다. 밀집 단계가 칩·배지로 번지면 AIT-09 값 드리프트가 다시 생긴다.
  - `#c25a12` 등 토큰 밖 색도 단계 정리 대상에 넣는다는 보완을 받아들인다. 색은 "글자·간격·모서리·그림자·색" 다섯 갈래로 함께 정리한다.
- X-02 설정 채움 2개·랜딩 CTA 2개: v1 SET-82·ONB-88과 같다. 규칙 위반 목록에 그대로 둔다. "블록 전체 클릭은 이미 상세 열기라 반복 동작 대체로 못 쓴다"는 반박은 맞다. accent-soft 경계 1.03~1.1:1은 ux2 측정과 같으므로 "글자 4.5:1 + 경계 3:1 또는 윤곽"을 한 규칙으로 쓴다.
- X-04 캘린더 대화창(안 D): **받아들인다. 두 가지를 고친다.**
  - 조건은 "비어 있지 않음"이 아니라 "**처음 연 값과 다름**(dirty)"이다. 기존 일정을 열고 아무것도 안 바꿨으면 Esc는 바로 닫는다. ux3 CAL-89 제안도 "수정이 있을 때만"이라 같은 뜻이다.
  - 확인은 겹친 모달이 아니라 **대화창 안 한 줄**("저장 안 한 변경이 있어요 [버리기] [계속 편집]")로 한다. 포커스는 [계속 편집]에 둔다. 이 상태에서 Esc를 다시 누르면 계속 편집이다. 버리기는 누르는 버튼으로만 한다.
  - 바깥 누르기는 `pointerdown`이 아니라 "누름과 뗌이 모두 바깥"일 때만 닫는다. 스크롤하다 배경을 짚어 닫히는 문제는 이것만으로도 줄어든다.
  - 공통 원칙 문구: "**Esc는 사용자가 쓴 글을 말없이 버리지 않는다.** 저장 단계가 없는 입력(빠른 입력)은 글을 남기고, 저장 단계가 있는 창은 한 번 묻는다."
  - "토스트가 사라지면 Ctrl+Z도 끝난다"를 규칙 문구에 넣는다. 토스트는 마우스·포커스가 올라가 있으면 멈추므로(Toast.tsx) 5초는 최소 시간이다.
- X-11 좁은 블록의 점선: **받아들인다.** X-07 안 A의 열 상한(최소 28px)이 들어가면 2px 점선은 보인다. 그래도 낭독기 이름에 "계획"을 넣는다(지금 이름은 "제목, 시각"뿐). 폭 기준 아이콘은 28px 블록에 넣을 자리가 없어 쓰지 않는다.
- X-12 잡힘 신호: **받아들인다.** 직접 조작의 응답은 모션 규칙(빈도 표)의 대상이 아니라 피드백이라는 구분이 맞다.
  - 규칙 문구: "끌기·길게 누르기·시트 끌기는 0ms로 손을 따라온다. 잡히면 즉시 그림자 한 단계 + 불투명도 변화. 놓아서 제자리로 돌아갈 때만 200ms drawer 곡선, 옮기기에 성공하면 즉시."
  - `scale(1.02)`는 쓰지 않는다. 밀집한 시간 그리드에서 글자가 흔들리고 이웃 블록을 덮는다.
  - 끌기 중 ghost는 X-11 판정대로 점선 계열로 바꾼다(CAL-93).
- X-13: 날짜 안 A, placeholder 안 B와 "지시문은 문장 그대로"에 이미 합의했다. 더 답할 것이 없다.
- 이음매(X-03 일정 삭제): 일정 삭제는 5초 되돌리기가 있으므로 위험색이 아닌 중립 보조 버튼이 맞다. "토스트가 유일한 안전망"이라는 우려는 남은 이견으로 교차리뷰 문서에 적는다. 반복 일정의 "이후 모두 삭제"는 범위 선택 창이 이미 확인 역할을 하므로 추가 확인을 두지 않는다.
