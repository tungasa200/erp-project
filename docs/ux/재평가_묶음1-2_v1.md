- 대상 커밋: feature/UX `d648565`(묶음 1, COM-19는 `e6670f1`), `68778ee`(묶음 2). 워킹트리의 미커밋 3a·3b 작업은 섞지 않았다.
- 방법
  - `git archive d648565 frontend shared`로 만든 임시 사본에서 mock 모드 개발 서버(5190)를 띄웠다. node_modules는 정션으로 빌려 썼다.
  - 사본 설정만 두 가지 바꿨다. vite 캐시를 사본 안으로 옮겼다(공용 node_modules/.vite를 건드리지 않게). 정션 실제 경로를 fs.allow에 넣었다(Pretendard 글꼴이 막혀 대체 글꼴로 그려지던 것을 막으려고).
  - agent-browser 세션은 `WY-ux`, 계정은 mock 데모 계정, 폭은 1280×800과 390×844, 테마는 기본(라이트)이다.
  - 접근성 스냅숏을 먼저 썼다. 계산 스타일·좌표·대비는 페이지 안에서 쟀다. 누르는 영역은 보이는 상자와 `::before`·`::after` 중 큰 값으로 쟀다.
  - COM-15는 사본을 운영 모드로 빌드해서 첫 묶음 크기를 쟀다.
  - 보조 점검: 묶음 1·2의 바뀐 줄에 `web-design-guidelines`(고정 사본)와 `impeccable` audit 관점을 하위 에이전트로 돌렸다(§4).
- 한계
  - mock은 fetch 단계를 바꾸므로 오프라인으로 바꿔도 API가 성공한다. 그래서 "오프라인에서 서버 요청이 실패하는" 경로는 이 환경에서 판정하지 않았다(LOG-40 일부).
  - 개발 서버에는 서비스 워커가 없어 오프라인 새로고침은 미측정이다.
  - 실제 터치, iOS 확대, 낭독기, PWA 독립 실행은 에뮬레이션으로 일부만 봤다. 나머지는 §5 실기기 목록(REL-07)으로 넘긴다.
- 판정 말: **해결**(의도대로 동작, 측정함) / **부분**(일부 경로·조건이 남음) / **미해결** / **새 결함**(이번에 처음 찾음).

## 1. 요약

- **판정 집계(묶음 1 ID 21개 + 묶음 2 ID 7개 + LOG-40·COM-01·02, 모두 31개)**
  - 해결 28: 묶음 1의 20개, 묶음 2의 6개, 재평가 대상 COM-01·02다.
  - 부분 2: LOG-40은 오프라인 새로고침이 미측정이라 부분이다. CAL-94는 배너가 있는 1280×800에서 아래 가장자리 자동 스크롤이 되지 않는다.

  - 새 결함 4: 높음 1, 낮음 3.
- **가장 큰 문제 (영향 순)**
  1. **UX-LOG-140 (높음, 새 결함, 묶음 1 이전부터 있던 결함):** 일지에 글자가 빈 줄이 하나라도 있으면 실적·계획 목록 전체가 저장되지 않는다. 그 사이 지운 줄과 고친 글은 확정할 때 사라지거나 되살아난다. 경고는 없다.
  2. UX-CAL-94 (부분): 미인증 배너가 있는 1280×800에서는 그리드 아래 가장자리가 창 밖(852px)에 있다. 끌어도 아래로 자동 스크롤되지 않는다.
  3. UX-COM-140 (낮음, 새 결함): 1280 사이드바의 현재 메뉴가 키 컬러 채움이다. 그래서 모든 화면에 채움이 하나 더 생긴다(X-02, 목업은 accent-soft).
  4. UX-LOG-141 (낮음, 새 결함): 일지에서 마지막 실적 줄을 지우면 포커스가 [＋ 실적 줄 추가]가 아니라 페이지 제목(H1)으로 간다.
  5. UX-COM-141 (낮음, 새 결함): 390 빠른 기록 시트의 [?]가 32×32이고 "자주 하는 업무" 칩 높이가 30px다(기준 44px).
- **잘된 점 (유지할 것)**
  1. 빠른 입력의 안전망이 정리됐다. Esc는 글을 남기고 포커스만 뺀다. 저장 직후 빈 칸에서 누른 Ctrl+Z는 앱 되돌리기로 간다. 일지 줄 삭제도 5초 되돌리기와 Ctrl+Z가 되고, 되돌리면 그 줄로 포커스가 돌아온다.
  2. 모바일 셸이 기준을 맞췄다.
     - 767px 이하에서 16px보다 작은 입력이 8개 경로에서 0개다.
     - 빠른 입력 높이는 48px다.
     - 시트에는 [저장] 52×44와 꺼진 이유가 있고, `enterKeyHint=done`이다.
     - 넓은 창은 하단 시트로 열리고 주 버튼이 엄지 영역(y 776~820)에 있다.
     - `scroll-padding`이 104px라 하단 탭이 포커스를 가리지 않는다(초점 이동 45개 중 가려짐 0).
  3. 낭독 영역이 앱에 하나로 모였다. 빠른 입력 해석, 오프라인·재연결, 팔레트 결과 수, 타이머 메시지가 모두 상태 영역으로 알려진다. 토스트 안 포커스 링은 흰색이다(바탕 #1A1C2B 기준 16.9:1).

  5. 기대 결과: 삭제가 저장된다. 실제 결과: 새로고침하면 "주간 영업 보고"가 다시 있다. 새로고침 대신 [확정]을 누르면 확정 문서 실적에 "주간 영업 보고"가 들어 있다.
  6. 탭을 닫거나 새로고침하면 `beforeunload` 경고가 뜬다. 앱 안 이동이나 [확정]에는 경고가 없다.
- 원인(소스): `useLogEditor.ts:61~66`. 실적이나 계획 목록에 글자가 빈 줄이 하나라도 있으면(`blank()`) 그 목록 전체를 보내지 않는다. 빈 줄을 채우거나 지울 때까지 같은 목록의 다른 수정(삭제·글 고침·순서 이동)도 서버에 가지 않는다. 화면에는 저장 상태 표시가 없다.
- 영향: 하루 마감 직전에 줄을 정리하는 흐름(줄 하나 추가 → 다른 줄 정리 → 확정)에서, 지운 줄이 확정 문서에 남거나 고친 글이 빠진다. 사용자는 화면에서 본 것과 확정 문서가 다르다는 것을 확정 뒤에야 안다.
- 제안: 빈 줄만 빼고 나머지 목록을 보낸다. 빈 줄은 편집 상태에만 두고, 서버 목록에는 넣지 않는다. 빈 줄이 남아 있는 채로 [확정]을 누르면 "빈 줄은 빼고 확정할게요" 한 줄로 알린다. 저장이 보류 중이면 "저장 안 된 변경" 표시를 둔다(LOG-40 제안과 같은 표시).
