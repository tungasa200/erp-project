## 0. 지금 모습

- 프로젝트 줄은 `색 · 이름 · 업무 n · [보관]`이다. 이름을 바꿀 곳이 없다. API(`PATCH /projects/{id}` name)는 이미 이름 변경을 받는다.
- 태그 칩은 `#이름 · 사용 수 · [✎]`이다. ✎를 누르면 그 자리에서 입력칸이 되고 [삭제]가 나온다. 저장은 Enter 또는 포커스가 칩을 떠날 때, 취소는 Esc다.
- 프로젝트 순서는 서버가 주는 순서(만든 순서)이고, 사이드바·필터·빠른 입력이 모두 이 순서를 쓴다.

## 1. 이름 바꾸기: 태그 칩과 같은 방식

### 1.1 줄 구성

| 상태 | 프로젝트 줄 (왼쪽 → 오른쪽) | 태그 칩 (지금, 비교) |
|---|---|---|
| 보통 | 손잡이 ⠿ · 색 · **이름** · 업무 n · **[✎]** · [보관] | #이름 · 사용 수 · [✎] |
| 편집 | 손잡이(꺼짐) · 색 · **[입력칸]** · 업무 n · [보관] | # · [입력칸] · [삭제] |

- **✎ 위치**: 태그와 같은 차례(`이름 · 수 · ✎`)로 업무 수 바로 뒤, [보관] 앞에 둔다. 모양은 태그 ✎와 같다: `.iconButton` 32×32 흰 원, 누르는 영역은 `::after`로 44×44. 낭독 이름 "{이름} 프로젝트 이름 바꾸기".
  - 프로젝트 줄 바탕이 흰 면이라 흰 원이 보이지 않는다. 그래서 프로젝트 줄에서만 `--color-surface-sunken` 면을 쓴다(태그는 회색 칩 위 흰 원으로 같은 대비).
- **편집 줄**: 이름 자리가 입력칸이 되고, 입력칸에 태그 편집과 같은 키 색 2px 테두리를 둔다. 입력칸 높이 36, 글자 크기와 굵기는 이름과 같다(14/600, 입력값이라 400이 아니라 이름과 같은 600). 이름 길이가 바뀌어도 줄이 출렁이지 않게 입력칸이 이름 칸 폭을 다 쓴다(`flex: 1 1 6em`).
  - 업무 수와 [보관]은 그대로 둔다. 태그 편집이 [삭제]를 보이듯 프로젝트도 줄 동작을 그대로 남긴다. Tab으로 [보관]에 가도 편집은 닫히지 않는다(포커스가 줄 안에 있음, 태그 P1-02-11과 같음).
  - 편집하는 동안 그 줄 손잡이는 끈다(이름을 고치다 끌리지 않게).

### 1.2 키·저장 동작 (태그와 같음)

| 동작 | 결과 |
|---|---|
| ✎ 누름 | 입력칸에 포커스, 글자 전체 선택(태그는 커서만 끝에 두는데, 프로젝트 이름은 통째로 바꾸는 경우가 많아 전체 선택. **태그도 같이 전체 선택으로 맞춘다**, 형제 일치) |
| Enter | 저장 → 보통 줄, 포커스는 ✎로 |
| Esc | 취소(원래 이름) → 보통 줄, 포커스는 ✎로. 고친 내용을 묻지 않는다(한 줄짜리, D-212 X-04의 "창 안에서 묻기"는 창에만) |
| 포커스가 줄 밖으로 | 저장. 누른 곳에 포커스를 둔다 |
| 한글 조합 중 Enter | 무시(지금 태그와 같음) |
| 이름이 그대로 | 요청 없이 닫기 |

- 저장해도 토스트를 띄우지 않는다(태그와 같음). 바뀐 이름이 그 자리와 사이드바에 바로 보이는 것이 결과다. 되돌리기도 없다(다시 ✎로 고친다).
- 저장 중에는 입력칸을 그대로 두고 두 번 보내지 않는다. 0.4초가 넘으면 입력칸 오른쪽에 작은 진행 표시를 둔다.

### 1.3 오류 안내

입력칸 아래 줄 전체 폭에 빨간 글자(13/600, `--color-danger`, `role="alert"`)로 보이고, 입력칸은 `aria-invalid`와 빨간 테두리로 바꾼다. 오류가 있으면 포커스가 줄을 떠나도 편집을 닫지 않는다(태그와 같음). 고쳐 쓰면 오류 글을 지운다.

| 경우 | 문구 | 비고 |
|---|---|---|
| 빈 이름(공백만 포함) | 프로젝트 이름을 적어 주세요 | 새 프로젝트 칸과 같은 문구. 요청 보내지 않음 |
| 이름이 겹침(409 DUPLICATE_NAME) | 같은 이름의 프로젝트가 있어요. 보관함도 확인해 주세요 | 보관한 프로젝트도 겹침에 들어간다(확정, 아래). 서버는 보관 여부를 구분하지 않으므로 한 문구로 둘 다 안내한다. 서버 detail("같은 이름이 이미 있어요.")은 쓰지 않고 화면 문구를 쓴다 |
| 50자 넘음 | (입력칸이 50자에서 멈춤) | 붙여 넣어 넘으면 서버 VALIDATION_FAILED → "이름은 50자까지 쓸 수 있어요" |
| 다른 곳에서 먼저 바뀜(VERSION_CONFLICT) | 토스트 "다른 곳에서 먼저 수정돼서 새로 불러왔어요. 다시 해 주세요" | 편집을 닫고 새로 불러온다(태그와 같음) |
| 그 밖의 실패 | 공용 오류 토스트(2.5, 문의 코드) | 편집은 열어 둔다 |

- 겹침 규칙(확정, WY-backend2 2026-10-28): 같은 사용자의 프로젝트 전체(보관 포함)에서 앞뒤 공백을 뺀 이름을 대소문자 구분 없이 비교한다. 자기 이름의 대소문자만 바꾸는 것(예: `wy` → `WY`)은 허용하고, 화면은 이를 "이름이 그대로"로 보지 않고 저장 요청을 보낸다.
- 새 프로젝트 칸의 겹침 문구(지금 "같은 이름의 프로젝트가 있어요")도 같은 규칙이라 같은 문구로 맞춘다(WY-frontend).

## 2. 순서 바꾸기

### 2.1 손잡이

- 줄 맨 앞(색 앞)에 손잡이 ⠿(점 6개 아이콘 16px, `--color-text-muted`)를 둔다. 보이는 크기 24×36, 누르는 영역은 `::after`로 44×44. 마우스를 올리면 `cursor: grab`, 면 `--color-accent-faint`.
- 손잡이는 **버튼**이다. 누르면 옮기기 메뉴가 열리고, 누른 채 움직이면 끈다. 낭독 이름 "{이름} 순서 바꾸기, n개 중 k번째".
- 프로젝트가 1개뿐이면 손잡이를 숨긴다(옮길 곳이 없음). 0개면 목록이 없다.
- 끄는 것은 손잡이에서만 시작한다. 줄 전체를 끌게 하면 ✎·[보관]을 누르다 끌린다.

### 2.2 끌기(마우스·터치)

| 단계 | 모습 |
|---|---|
| 잡기 | 손잡이를 누르고 6px 넘게 움직이면 시작. 그 줄이 떠오른다: 흰 면, 그림자 `--shadow-2`, `cursor: grabbing`, 살짝 기울이지 않음(정돈된 도구 느낌 유지) |
| 옮기는 중 | 원래 자리는 빈 칸(점선 1.5px `--color-border`, 줄 높이 그대로)으로 남고, 놓을 자리에 키 색 2px 선과 왼쪽 끝 점(6px 원)을 보인다. 다른 줄은 150ms ease-out으로 비켜선다. 움직임 줄이기 설정이면 비켜서는 애니메이션 없이 선만 옮긴다 |
| 놓기 | 그 자리에 들어가고 바로 저장한다(2.4). 놓은 줄에 0.8초 동안 옅은 키 색 면(`--color-accent-softer`)이 머물렀다 사라진다 |
| 목록 밖·Esc | 취소. 원래 자리로 돌아간다 |
| 위·아래 끝 | 목록 끝 40px 안에서는 페이지를 천천히 굴린다 |

### 2.3 옮기기 메뉴(키보드·화면 낭독기·휴대폰)

- 손잡이를 누르면(Enter·Space·클릭·탭) 업무 줄 [⋯] 메뉴와 같은 모양의 팝오버가 손잡이 아래에 열린다(`.rowMenuList`: 흰 면, `--shadow-2`, 항목 높이 44, 모든 폭 같음).
- 항목: **위로 옮기기 · 아래로 옮기기 · 맨 위로 · 맨 아래로**. 첫 줄은 위로·맨 위로를, 끝 줄은 아래로·맨 아래로를 끈다(`aria-disabled`, 흐린 글자, 포커스는 건너뜀).
- 화살표로 항목 이동, Enter로 실행, Esc로 닫고 손잡이로 포커스. 메뉴를 열면 첫 켜진 항목에 포커스.
- 실행하면 메뉴를 닫고, 옮겨진 줄의 손잡이에 포커스를 둔다(같은 줄을 계속 옮길 수 있게). 놓기와 같은 옅은 면이 0.8초 머문다.
- 사용자가 고른 "위·아래 버튼"을 줄마다 상시 두지 않고 손잡이 메뉴 안에 넣은 이유: 줄마다 44px 버튼 두 개가 늘면 390에서 이름 칸이 사라지고, 순서 바꾸기는 자주 하지 않는 일이다. 대안은 4장 Q2.

### 2.4 저장과 실패

- 놓거나 메뉴로 옮기면 화면 순서를 먼저 바꾸고(낙관적) 전체 순서를 보낸다. 연달아 옮기면 마지막 순서만 보낸다(앞 요청이 진행 중이면 끝난 뒤 최신 순서로 한 번 더).
- 바뀐 순서는 같은 쿼리를 쓰는 곳에 바로 보인다: 사이드바 프로젝트 목록, 업무 목록 프로젝트 필터(데스크톱·휴대폰 필터 시트), 빠른 입력 프로젝트 후보, 업무 상세 프로젝트 고르기, 캘린더 프로젝트 필터. 보관함(보관한 날짜순)과 통계(시간순)는 자기 정렬을 그대로 쓴다.
- **성공**: 토스트 없음. 화면 낭독기에만 알린다(공용 polite 알림 영역): "{이름}을 n개 중 k번째로 옮겼어요". 끌어서 놓았을 때도 같은 말을 알린다.
- **실패**: 화면 순서를 마지막으로 저장된 순서로 되돌리고(150ms, 움직임 줄이기면 즉시) 토스트 "순서를 저장하지 못했어요. 다시 해 주세요"(5xx면 문의 코드). 포커스는 옮기려던 줄의 손잡이에 둔다.
- **다른 곳에서 먼저 바뀜**(409 PROJECT_ORDER_STALE: 보낸 id 묶음이 서버와 다름, 예: 다른 기기에서 프로젝트를 만들거나 보관): 새로 불러와 서버 순서로 되돌리고 토스트 "프로젝트 목록이 바뀌었어요. 목록을 새로 불러왔어요".
- API: `PUT /api/worklog/projects/order`에 보관하지 않은 프로젝트 id 전체 배열. 순서만 바꿀 때는 프로젝트 version이 오르지 않으므로 이름 편집과 부딪히지 않는다.
- **오프라인**: 손잡이와 ✎를 끈다. title "연결되면 바꿀 수 있어요"(사이드바 [+]와 같은 방식).
- 새 프로젝트는 맨 아래에 붙는다. 보관함에서 되돌린 프로젝트도 맨 아래(4장 Q3).

### 2.5 화면 낭독기·고대비

- 목록은 지금처럼 `<ul aria-label="프로젝트 목록">`. 끌기는 포인터 전용이고, 같은 일을 메뉴로 다 할 수 있다(WCAG 2.5.7 끌기 대안).
- 고대비 모드: 떠오른 줄은 그림자 대신 2px `CanvasText` 테두리, 놓을 자리 선은 `Highlight`, 빈 칸은 점선 `GrayText`. 편집 입력칸 테두리는 `Highlight`.

## 3. 390(휴대폰)

- 줄: `⠿ · 색 · 이름 · 업무 n · ✎ · [보관]`이 한 줄에 들어가지 않으면 지금처럼 업무 수·✎·[보관]이 다음 줄 오른쪽으로 내려간다. 손잡이와 색은 첫 줄 왼쪽에 남는다. 이름 칸은 최소 6em.
- 끌기: 손잡이를 **누르는 즉시** 끌 수 있다(손잡이에만 `touch-action: none`). 길게 누르기는 쓰지 않는다: 숨은 동작이라 찾기 어렵고, 손잡이가 작아 페이지를 굴리다 잘못 끌릴 일이 적다. 탭(6px 안 움직임)은 메뉴를 연다.
- 메뉴는 데스크톱과 같은 팝오버다(업무 줄 [⋯]도 휴대폰에서 같은 팝오버). 화면 아래 끝에 가까우면 손잡이 위로 연다.
- 편집: ✎를 누르면 입력칸이 이름 자리를 차지하고 키보드가 올라온다. 업무 수·[보관]은 둘째 줄에 있다. 오류 글은 입력칸 바로 아래.
