- 작성: WY-ux2, 2026-10-12 · 기준: `docs/ux/평가기준표_v1.md` · 대상: 운영 https://wy-worklog.com · 계정: TEST_A(`_ALT` 값으로 로그인됨)
- 범위: SCR-REC-01, SCR-TASK-01~04, SCR-LOG-01~06, SCR-STAT-01, 후보 'work_log 순차 조회'. SCR-FORM-01·02는 화면정의서 v2.1에 "U1(출시 후)"로 적혀 있고 구현·경로가 없어 평가하지 않았다(`/settings/forms` 없음).
- 폭: 1280·390은 전 화면, 360은 넘침만(6화면 모두 가로 넘침 없음), 768은 일지 상세 1화면. 테마는 기본만(바꾸지 않음).

## 요약

### 가장 큰 문제 5개 (영향 순)
1. **UX-LOG-40** 오프라인에서 일지에 입력이 되는데 "입력할 수 있어요" 배너와 달리 저장이 되지 않고, 다음 수정 전에 나가면 글자가 조용히 사라진다(데이터 손실).
2. **UX-LOG-42** 390px 일지 실적 표가 600px인데 화면은 326px라 결과·진행률·이동·삭제가 화면 밖에 있고 가로 스크롤 단서가 없다.
3. **UX-LOG-44·45** 하루 마감: 1단계에서 주 버튼이 "그대로 다음"(처리 건너뜀)이고, 마지막 미리보기는 개수만 보여 줘 "무엇을 확정하나"가 한눈에 안 보인다. 방금 처리한 확인 대기 2건이 "실적 0건"으로 나온다.
4. **UX-LOG-41** 긴 일지(실적 14줄)에서 [확정]·[내보내기]가 스크롤 맨 위에 있어 맨 아래 작성 중에는 화면 밖(−376px)이다.
5. **UX-STAT-67** 통계: 확정 기록이 7일 안 되면 화면 전체가 막히고, 켜진 기간 버튼은 눌러도 변화가 없다. 이 계정은 이미 기록이 있는데 "1일 남았어요".

### 잘된 점 3개 (유지)
1. 확인 대기 처리·업무 추가·보관·완료 모두 **되돌리기 토스트**가 있다(보관은 확인창 없이 바로, 대신 복원 가능). 실수 비용이 낮다.
2. 일지 화면이 **내보낼 파일과 같은 서식**(결재란·표)이라 훑어보기와 제출 결과의 차이가 작다. 내보내기는 홈 카드에서 2번 눌러 끝난다(확정 → 내보내기 → 내려받기).
3. 업무 완료 결과 팝오버(SCR-TASK-03)는 "Enter 저장 · Esc 건너뛰기"를 보여 주고 건너뛸 수 있다. 하루 마감 NFR-12(60초)는 클릭 수로 보면 여유가 있다(아래 클릭 수).

### 클릭·키 수 (실측)
| 흐름 | 클릭 | 비고 |
|---|---|---|
| 홈 → 하루 마감 확정(확인 대기 0건) | 3 (하루 마감 → 다음 → 마감하고 확정) | 프로필 요청이 끼면 +1(나중에) |
| 확인 대기 2건 처리 후 마감 | 6 (하루 마감 → 확인 대기 처리 → 했어요 → 1건 모두 했어요 → 다음 → 마감하고 확정) | "2건 모두 했어요"를 바로 누르면 5 |
| 확정 → PDF 받기 | 2 (내보내기 → 내려받기) | 확정 완료 창에서 이어서, 인증된 계정 기준 |
| 확정 해제 → 다시 확정 | 6 (일지 보기 → 확정 해제 → 해제 확인 → 홈 → 하루 마감 → 다음 → 마감하고 확정은 7) | 해제 확인창 1번, 확인 대기 0건·프로필 요청 없음 기준 |
| 기록 추가 창에서 키보드로 저장 | Tab 9번 | Enter는 줄바꿈, Ctrl+Enter 없음(UX-REC-58) |

## 지적

### UX-LOG-40 (오프라인에서 일지 입력이 막히지 않고, 저장도 안 돼 글자가 조용히 사라진다)
- 화면: SCR-LOG-02 · 폭/테마: 1280 기본 · 축: 4·3 · 심각도: 높음 · 구분: 구현 차이
- 문제: 네트워크를 끊으면 상단에 "연결이 끊겼어요. 다시 연결되면 입력할 수 있어요"가 뜨지만 이슈 칸은 `disabled`·`fieldset[disabled]`가 아니라 계속 입력된다. 다시 연결하고 8초를 기다려도 서버 값은 오프라인에서 친 글자가 빠진 그대로고(`fetch /api/worklog/logs/daily/…`로 확인), 화면은 "저장됨"·오류 표시가 없다. 한 글자를 더 쳐야 그때 전체가 저장됐다.
- 영향: 이동 중 지하철에서 쓴 일지를 연결이 돌아온 뒤 화면을 닫으면 사라진다. 배너 문구와 실제 동작이 달라 사용자가 안전하다고 믿는다.
- 제안: 오프라인에서는 일지 입력 칸도 읽기 전용으로 두거나(배너 문구와 일치), 입력은 허용하되 재연결 시 자동 재저장과 "저장 안 된 변경이 있어요" 표시를 둔다. 둘 중 하나는 반드시.
- 근거: 휴리스틱 1(시스템 상태 가시성)·5(오류 예방), 기준표 축 4 "오프라인". 재현 2회(입력 후 재연결 8초 대기, 서버 값 비교).
- 증거: `UX-LOG-offline-lost-1280.png`, `LOG-02-offline-1280.png`. 다만 이 환경에서 오프라인 전환 뒤 `reload`가 두 번 멈춰 새로 고침 뒤 확인은 못 했다(미측정).

### UX-LOG-41 (긴 일지에서 확정·내보내기 버튼이 따라오지 않는다)
- 화면: SCR-LOG-02 · 폭/테마: 1280·390 기본 · 축: 2·3 · 심각도: 중간 · 구분: 의도 문제
- 문제: 실적 14줄(80자 긴 줄 포함)에서 맨 아래(이슈 칸)까지 스크롤하면 [확정] 상단 버튼이 −376px로 화면 밖이다. 상단 바에 `position: sticky`가 없다(조상 sticky 0개).
- 영향: 하루 수십 줄 일지에서 이슈를 쓰고 확정하려면 다시 맨 위로 올라가야 한다. 하루에 한 번 반복되는 마무리 동작이다.
- 제안: 문서 하단 또는 화면 하단에 확정 동작을 한 번 더 두거나 헤더를 sticky로. [스킬 대기: frontend-design]
- 근거: 기준표 2장 "긴 일지(하루 수십 줄)에서의 훑어보기", 휴리스틱 7(효율). 측정: `getBoundingClientRect().top = −376`.
- 증거: `LOG-02-long-1280.png`.

### UX-LOG-42 (390px 실적 표가 가로로 잘리고 단서가 없다)
- 화면: SCR-LOG-02 · 폭/테마: 390 기본 · 축: 7·6 · 심각도: 중간 · 구분: 의도 문제
- 문제: 표(600px)가 스크롤 상자(326px) 안에 들어 있어 결과·진행률 열과 위·아래·삭제 버튼이 화면 밖이다. 스크롤 상자는 `overflow-x: auto`지만 그림자·가장자리 단서(mask 없음)가 없고, 오른쪽에 일부 보이는 입력 상자가 유일한 단서다. 다른 두 표(작성자 표 229, 문서 표 326)는 맞는다.
- 영향: 모바일에서 결과 한 줄을 쓰거나 줄을 지우고 순서를 바꾸려면 표를 옆으로 밀어야 하는 것을 알아내야 한다. 실기기에서는 스크롤과 입력 포커스가 충돌할 수 있다(실기기 필요).
- 제안: 모바일에서는 줄마다 카드형(제목 위, 결과 아래, 도구 오른쪽 위)으로 접거나, 우측 페이드 단서를 둔다.
- 근거: 기준표 축 7 "넘침·꺾임", 휴리스틱 10(도움말·가시성). 측정: `scrollWidth 600 / clientWidth 326`, 도구 버튼 보이는 28px+`::after` 44px(누르는 영역은 통과).
- 증거: `LOG-02-390.png`.

### UX-LOG-43 (실적 표 열 폭이 내용과 어긋난다)
- 화면: SCR-LOG-02 · 폭/테마: 1280·768 기본 · 축: 1·4 · 심각도: 낮음 · 구분: 구현 차이(미확정: 서식명세가 고정 폭일 수 있음)
- 문제: "업무 내용" 열이 약 140px로 좁고 "결과"는 비어 있어도 넓다. 80자 제목이 6줄로 꺾이며(1280에서 행 하나가 150px), 진행률·프로젝트 열은 대부분 비어 있다.
- 영향: 긴 업무 제목에서 한 줄이 표를 길게 늘려 훑어보기가 나빠진다.
- 제안: 업무 내용 열에 남는 폭을 주고(결과와 비율 조정) 진행률 열은 값이 있을 때만 폭을 쓴다.
- 근거: 측정 `업무 내용 158x32`(입력 상자), 줄 높이 150px(긴 행). 서식명세(`docs/업무일지_서식명세.md`)의 열 비율은 읽지 않았다(미측정).
- 증거: `LOG-02-long-1280.png`, `LOG-02-768.png`.

### UX-LOG-44 (하루 마감 1단계: 주 버튼이 "그대로 다음", 대기 항목은 보이지 않는다)
- 화면: SCR-LOG-03 · 폭/테마: 1280 기본 · 축: 1·2 · 심각도: 중간(빈도가 높아 한 단계 올림) · 구분: 의도 문제
- 문제: "확인 대기 기록이 2건 있어요" 창에서 채움(accent) 주 버튼이 [그대로 다음]이고 [확인 대기 처리]는 보조(회색)다. 어떤 2건인지(제목·날짜)는 창에 없고, 처리하려면 패널을 한 번 더 열어야 한다.
- 영향: 가장 눌리기 쉬운 길이 "대기를 안 처리하고 확정"이라 일지에 실적이 빠진다. 사용자는 무엇을 건너뛰는지 모른다.
- 제안: 창에서 2건을 이름과 함께 바로 보여 [모두 했어요] 주 버튼, [하나씩 확인] 보조, [그대로 다음]은 텍스트 링크로 낮춘다.
- 근거: 휴리스틱 5·6(오류 예방, 기억보다 인식). 기준표 "확인 대기 처리까지 걸리는 클릭". 클릭 수는 위 표.
- 증거: `LOG-03-step1-1280.png`, `REC-pending-1280.png`.

### UX-LOG-45 (하루 마감 마지막 단계 미리보기가 개수뿐이고, 방금 처리한 건이 0건으로 나온다)
- 화면: SCR-LOG-03 · 폭/테마: 1280·390 기본 · 축: 1·2 · 심각도: 중간 · 구분: 의도 문제
- 문제: 3/3 미리보기는 "실적이 없어요… 실적 0건 · 다음 근무일 계획 1건"만 보여 준다. 처리한 확인 대기 2건은 10/6 기록이라 오늘 일지에는 들어가지 않는데, 창은 그 이유를 말하지 않는다. 실제 확정되는 줄(제목)은 없다.
- 영향: "확정하면 무엇이 일지에 남나"를 확인하지 못한 채 [마감하고 확정]을 누른다. 확정한 뒤 "내가 처리한 2건은 어디 갔지?"가 생긴다.
- 제안: 미리보기에 실제 줄(실적 3줄 미리, 계획 줄)을 보이고, 다른 날짜 기록은 "10/6 기록 2건은 10/6 일지에 들어가요 [보기]"로 안내한다.
- 근거: 휴리스틱 1(상태 가시성). 기준표 "무엇을 확정하는지 한눈에".
- 증거: `LOG-03-step3-1280.png`, `LOG-03-step3-390.png`.

### UX-LOG-46 (확정 완료 창에 요약·해제 안내가 없다)
- 화면: SCR-LOG-03 · 폭/테마: 1280 기본 · 축: 2 · 심각도: 낮음 · 구분: 의도 문제
- 문제: "오늘 일지를 확정했어요"에 내용 요약도 [되돌리기] 토스트도 없다. 되돌리려면 [일지 보기] → [확정 해제] → 확인창 3번. 다른 흐름(업무 보관·확인 대기)은 되돌리기 토스트가 있어 일관되지 않다.
- 영향: 실수로 확정한 직후 바로 되돌릴 수 없다(일지 확정은 결재 제출과 가까워 실수 비용이 크다).
- 제안: 확정 직후 토스트에 [되돌리기]를 두고(해제 사유 없이), 완료 창에는 "실적 N건·계획 N건" 한 줄을 넣는다.
- 근거: 휴리스틱 3(사용자 통제), 기준표 "실수했을 때 되돌릴 수 있는가".
- 증거: `LOG-03-done-1280.png`.

### UX-LOG-47 (확정 해제 확인창: 되돌릴 수 있는 동작에 위험 색, 모바일에서 창이 화면을 채운다)

- 제안: 중립(accent) 채움으로, 창 높이는 내용에 맞춘다.
- 근거: 기준표 축 5(같은 의미는 같은 모양). 측정은 스크린숏 눈 판정(미측정: 창 높이 px).
- 증거: `LOG-04-390.png`.
