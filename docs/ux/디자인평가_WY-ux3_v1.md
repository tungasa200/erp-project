# 디자인 평가 보고서: WY-ux3 (캘린더·설정·알림·인증·랜딩·메일) v1

- 작성: WY-ux3, 2026-10-12. 기준: `docs/ux/평가기준표_v1.md`. 대상: 운영 https://wy-worklog.com, 계정 TEST_L(첫 시도에 성공, `_ALT` 안 씀).
- 폭: 1280·390·360(넘침 16개 화면), 768(캘린더 주·설정 일반). 테마: 기본 + 청록·웜 베이지 1회(저장 후 기본으로 되돌림, 되돌린 값 `#4B3FD6`/`#F2F4FA` 확인).
- 스크린숏: `docs/ux/evidence/WY-ux3/` (로컬만, 계정 메일은 가리거나 파일을 지움).
- **평가 한계(중요)**: 일정 생성(API 호출 1회, UI 저장 1회)이 자동 모드 분류기에 "Modify Shared Resources"로 거부돼 우회하지 않고 쓰기를 건너뜀. 따라서 캘린더는 **빈 계정**으로 봤고, 겹침·긴 제목·끌기·계획/실제 구분·알림 항목은 소스 읽기와 산술로만 평가했다(해당 지적에 "미측정(데이터)"을 붙임). 테마 저장은 거부되지 않아 수행했다.
- `impeccable detect` CLI는 이 PC에 없어 실행하지 못함(AI 티는 눈 판정만). D-200 스킬 3개는 설치 전.

## 요약

### 가장 큰 문제 5개 (영향 순)
1. **UX-CAL-70** 겹친 일정의 열 폭이 산술로 무너진다. 주 보기 1280에서 하루 열 57px라 3개만 겹쳐도 블록 폭 15px, 12개면 0.8px. "+n" 묶음이 시간 그리드에는 없다.
2. **UX-CAL-71** 일 보기가 가장 넓어야 하는데 1280에서 시간 그리드 열이 약 122px(좌 사이드바·우 업무 패널·"이날의 기록"에 눌림). 정의서 "블록이 넓어 메모 일부까지"와 반대.
3. **UX-AUTH-85** 390 처리방침 국외 이전 표 7열 760px가 358px 상자에서 가로 스크롤. 첫 두 열만 보이고(나머지 5열 숨김) 행 높이 약 200px, 스크롤 단서 없음.
4. **UX-SET-77** 키 컬러 청록·초록·주황이면 버튼 글자 대비 4.10~4.32:1로 4.5:1 미달, 강조색 글자도 3.5~3.9:1. 저장 검사는 3:1만 본다.
5. **UX-MAIL-91** 인증번호 메일 제목은 코드를 뺐지만(D-41) 본문 첫 줄 뒤에 코드가 바로 와서, 숨김 프리헤더가 없으면 메일 목록 미리보기에 코드가 실릴 수 있다(미측정, 실제 Gmail 필요).

### 잘된 점 3개 (유지할 것)
1. **로그인·가입·비밀번호 찾기 오류 처리**: 빈 제출에서 첫 오류 칸으로 포커스 이동, `aria-invalid`+`aria-describedby`, 약관 오류는 묶음 아래에 한 줄(REL-09 규칙이 구현에 반영됨). 가입은 입력 3칸 + 전체 동의 1번이면 끝.
2. **랜딩**: 390·1280 모두 첫 화면에서 한 줄 제목, 한 문장 설명, 주 버튼 하나(+보조 로그인), 예시 카드로 3초 안에 무엇인지 보인다. 가로 넘침 없음.
3. **알림 권한 요청 시점**: 하루 마감 알림을 켜기 전에는 허용 버튼이 비활성이고 이유 문구가 보이며, "푸시를 허용하지 않아도 알림은 앱 안에 모여요" 안내가 있다. 테마는 선택이 미리보기에 즉시 보이고 저장 전에는 앱이 바뀌지 않아 되돌리기 쉽다.

## 지적

### UX-CAL-70 (겹친 일정의 열 폭이 좁아져 읽기·누르기 불가)
- 화면: SCR-CAL-01 · 폭/테마: 1280·390 기본 · 축: 4·6 · 심각도: 중간 · 구분: 의도 문제
- 문제: 시간 그리드 블록 폭이 `100%/겹침열수 - 4px`(TimeGrid.tsx `blockStyle`)이고 열 수 상한·"+n" 묶음이 없다. 겹침 묶음의 열 수는 묶음 안 최대 열 번호 +1(layout.ts `packColumns`)이라 연쇄로 겹치면 묶음 전체가 가장 좁은 열 폭을 따른다. 월 보기만 칩 3개 + "+n개 더보기"가 있어 보기마다 규칙이 다르다.
- 영향: 회의가 몰린 날(3개 이상)부터 제목이 안 읽히고, D-76 예외 조건(24×24px)도 깨진다.
- 제안: 열 수가 3을 넘으면 4번째부터 "+n" 묶음 블록(누르면 그 시간대 목록 팝오버), 또는 최소 열 폭 24px 아래로는 겹침을 접는다.
- 근거: 산술(1280 주 열 402px/7=57px, 일 열 122px, 390 주 열 288px/7=41px) → 겹침 n개 폭: 주 1280 n=2 24px·n=3 15px·n=4 10px·n=12 0.8px, 일 1280 n=3 36px·n=12 6px. WCAG 2.5.8, 닐슨 7(유연성), 정의서 CAL-01 "겹치는 일정은 나란히 배치". **미측정(데이터)**: 12개 겹침을 만들지 못해 실제 렌더 미확인.
- 증거: `docs/ux/evidence/WY-ux3/UX-CAL-70-week-1280.png`(빈 주, 열 폭 측정), 소스 `frontend/src/calendar/TimeGrid.tsx:90-95`, `layout.ts`.

### UX-CAL-75 (빈 달력·목록 빈 상태에 만들기 행동이 없다)

### UX-CAL-76 (앱 전체가 한 덩어리 번들: 랜딩 방문자도 캘린더·통계까지 받는다)
- 화면: SCR-CAL-01 첫 진입(및 SCR-AUTH-01) · 폭/테마: 전체 · 축: 4·7 · 심각도: 낮음 · 구분: 구현 차이
- 문제: `index-*.js` 하나가 디코드 841KB(brotli 전송 약 267KB), CSS 224KB. `router.tsx`에 `lazy()`가 0건이라 랜딩·로그인·캘린더·통계가 같은 번들이다.
- 영향: 처음 온 사람이 랜딩을 보기 전에 앱 전체를 받는다. 재방문은 SW 캐시로 완화(전송 0 확인).
- 제안: 라우트 단위 `lazy()`(캘린더·통계·설정·공개 화면 분리). 번들 크기 정리는 리드 몫.
- 근거: 측정(리소스 타이밍 디코드 크기, `curl -H 'Accept-Encoding: br'` 266,576B). **미측정**: 저속망 체감 시간·FCP.
- 증거: 측정값.

### UX-SET-77 (키 컬러 청록·초록·주황이면 버튼 글자·강조 글자가 AA 미달)
- 화면: SCR-SET-04(테마)와 앱 전체 · 폭/테마: 390 청록+웜 베이지 · 축: 6 · 심각도: 중간 · 구분: 의도 문제
- 문제: 키 컬러 저장 검사는 강조색 대 배경 3:1(비텍스트)만 본다(theme.ts `MIN_ACCENT_CONTRAST`). 그런데 그 색이 버튼 배경 위 글자·강조색 글자로 쓰인다. 계산값: 청록 `#0E8A7E` 흰 글자 4.24:1, 초록 `#2F8F3E` 4.10:1, 주황 `#D9590B` 진한 글자 4.32:1(모두 4.5:1 미달), 강조색 글자 대 배경 청록 3.85·초록 3.73·주황 3.55:1(쿨 그레이). 실화면: 청록 테마 `인증하기` 버튼 14px/800 흰 글자, 배경 rgb(14,138,126) = 4.24:1.
- 영향: 기능은 되지만 14px 버튼 글자가 AA 미달. 키 컬러 8종 중 3종(37%)이 해당.
- 제안: 글자색을 흰색/진한색 중 큰 쪽이 아니라 4.5:1을 만족하는 색 단계(accent를 어둡게 조정한 `accent-ink`)로 계산하거나, 저장 검사를 "on-accent 글자 4.5:1"로 올린다. 결정은 WY-design·사용자(D-185는 3:1).
- 근거: WCAG 1.4.3(4.5:1), 계산 스크립트(8색×3배경). 보라 6.41:1·파랑 4.41·빨강 4.44·분홍 4.53(배경 대비)은 통과 또는 경계.
- 증거: `UX-SET-77-390.png`, `SET-theme-1280.png`.

### UX-SET-78 (1280 테마 화면에서 저장 버튼이 첫 화면 밖)
- 화면: SCR-SET-04 · 폭/테마: 1280×800 기본 · 축: 2·3 · 심각도: 낮음 · 구분: 구현 차이
- 문제: 저장·기본값으로 버튼이 배경 4종 아래(y 947~993)로 첫 화면(800) 밖이고 정적 배치다. 390·360은 하단 고정 바라서 일관되지 않다. 선택이 미리보기에는 즉시 보이지만 앱에는 저장해야 반영된다는 안내가 첫 화면에 없다.
- 영향: 색을 고르고 저장을 못 찾아 "안 바뀌었다"고 느낄 수 있다.
- 제안: 데스크톱도 카드 하단 고정(sticky) 또는 변경이 생기면 미리보기 옆에 저장 표시.
- 근거: 측정(저장 버튼 top 947 > innerHeight 800), 닐슨 1(상태 보임).
- 증거: `SET-theme-1280.png`.
