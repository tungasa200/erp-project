# 디자인 방향 교차리뷰 v1.1 (2026-10-12, WY-ux 판정)

- 목적: 디자인 평가 v1.1에서 방향이 갈린 쟁점 13개(X-01~13)를 세 평가 세션이 서로 반박한 뒤, 리드(WY-ux)가 판정한다. 반대 의견은 지우지 않고 남긴다(D-211).
- 이 문서는 `WY-design` 묶음 0(결정 먼저)의 입력이다. 판정은 평가 세션의 추천일 뿐이다. 화면정의서·토큰을 바꾸는 결정은 `WY-design`과 사용자가 한다.
- 원문
  - 안: 리드 `디자인평가_WY-ux_v1.1.md` 부록 A, ux2 `디자인평가_WY-ux2_v1.1.md` 부록 A, ux3 `디자인평가_WY-ux3_v1.1.md` 부록 A
  - 반박: 각 보고서 부록 B
  - 재반박: 각 보고서 부록 C
- 절차: 안 → 다른 두 세션 반박 → 안 낸 세션 재반박(한 번) → 리드 판정. 모든 쟁점이 이 절차를 마쳤다.
- 근거 표기: 주 근거는 impeccable critique·audit, 보조 근거는 web-design-guidelines(WDG)·frontend-design(FD)·emil-design-eng(emil)이다. 측정값은 원문에 있다.

## X-01 토큰 단계 (COM-14, LOG-57)
- 안(리드)
  - 안 A: 지금 많이 쓰는 값으로 단계를 정한다. 글자 12·13·14·16·18·22·28·34, 간격 4·8·12·16·24·32, 모서리 8·12·20·pill, 그림자 3단계.
  - 안 B: 1.2배 척도로 새로 짠다.
- 반박
  - ux2: 안 A에 동의하고 두 가지를 보탰다.
    - 반 픽셀은 아래 단계로 보낸다(13.5 → 13). 표 줄 간격을 지키기 위해서다.
    - 일지 문서 서식(`paper.module.css`)은 단계 밖으로 둔다. 내보내기 결과와 같아야 한다.
  - ux3: 안 A에 동의하고 두 가지를 보탰다.
    - 캘린더 블록 전용 단계 11·12를 둔다. 24px 블록 안 한 줄 때문이다.
    - `#c25a12` 같은 토큰 밖 색도 정리 대상에 넣는다.
- 재반박(리드): 넷 다 받아들인다. 캘린더 단계만 범위를 좁힌다.
  - 11은 `--text-dense`로 두고 시간 그리드 블록 안에서만 쓴다.
  - 칩 11.5px는 12로 올린다.
- **판정: 안 A + 보완 4.**
  - 본문은 14(입력·목록), 보조는 13이다.
  - 반 픽셀은 아래 단계로 보낸다.
  - 밀집 단계 11은 시간 그리드 블록 전용이다.
  - 인쇄 서식은 "서식 전용 단계"로 따로 적는다.
  - 색도 단계 정리 대상이다.
  - 767px 이하 입력은 16px이다(COM-10).
- 사유
  - 선언의 60%가 바뀌지 않아 QA 범위가 작다.
  - 안 B는 14 → 17 점프 때문에 일지 표가 넓어지고(LOG-42가 나빠짐), 캘린더 24px 블록에 글자가 들어가지 않는다(셋 모두 같은 지적).
  - 주 근거는 impeccable audit(Theming·Implementation)이다. 보조 근거는 FD "위계와 상관없이 같은 모서리"와 AIT-09다.
- 남은 이견: 없음.
- WY-design 결정 문구(제안): "글자 8단계 + 밀집 1단계(캘린더 블록 전용), 간격 6단계(4px 배수), 모서리는 위계별 3단계 + pill, 그림자 3단계. 반 픽셀 금지. 일지 문서 서식은 별도 서식 단계."

## X-02 주 버튼 하나 규칙 + 홈 머리 (HOME-01·02, REC-59, SET-82, ONB-88, LOG-44)
- 안(리드)
  - 안 A: 엄격하게 "한 시야에 채움 하나"로 한다.
  - 안 B: 영역형으로 패널마다 하나를 허용한다.
  - 안 C: 시간대형 홈. 근무 종료 뒤에는 [하루 마감] 띠를 올린다.
  - 추천은 A + C이다. 목록 안 반복 동작은 accent-soft로 둔다.
- 반박
  - ux2
    - accent-soft는 바탕 대비가 1.03:1이라 경계가 보이지 않는다. "글자 4.5:1 + 경계 3:1"을 조건으로 둔다.
    - 동작이 셋인 행(확인 대기)은 행 전체 클릭으로 대신할 수 없다.
    - 일지 `.bar`는 이미 규칙을 따른다.
  - ux3
    - 설정 채움 2개(SET-82)와 랜딩 CTA 2개(ONB-88)가 위반이다.
    - 캘린더 블록 클릭은 이미 상세 열기라 반복 동작을 대신할 수 없다.
    - accent-soft 경계를 다시 계산하면 1.03~1.1:1이다.
- 재반박(리드): 두 조건을 받아들였다. "동작이 둘 이상인 행은 accent-soft + 윤곽".
- **판정: 안 A + 안 C.**
  - 규칙
    - 한 시야에 키 컬러 채움은 하나다.
    - 목록 안 반복 동작은 accent-soft 바탕 + accent-ink 글자로 한다(글자 4.5:1, 경계 3:1 또는 윤곽).
    - 동작이 둘 이상인 행은 accent-soft + 윤곽 조합이다.
    - 상태 강조는 숫자 색으로만 한다.
  - 홈
    - 빠른 입력을 머리 전체 폭의 주인공으로 둔다.
    - 타일은 한 줄 요약으로 접는다(HOME-02·10).
    - 채움은 [하루 마감] 하나, 모바일은 하단 + 하나다.
- 사유
  - critique 인지 부하 실패 2개(단일 초점·시각 위계).
  - FD "큰 숫자 + 작은 라벨 + 강조는 기본 처리", "대담함은 한곳에".
  - 안 B는 지금 문제(채움 3~4개)를 규칙상 허용해 버린다.
- 남은 이견: 안 C의 기본값. 근무 종료 시각을 설정하지 않은 사용자에게 띠를 언제 올릴지 정해야 한다. 리드 제안은 "18:00, 또는 그날 마지막 일정 끝 + 30분 중 늦은 쪽"이다. WY-design이 정한다.
- 위반 목록: 홈 1280 채움 3, 390 채움 4. REC-59, SET-82, ONB-88, LOG-44.

## X-03 위험색 범위 (LOG-47, TASK-63, SET-81)
- 안(ux2): 안 A. 위험색은 되돌릴 수 없는 동작(탈퇴·영구 삭제)에만 쓴다. 확정 해제는 중립 채움, 보관은 중립 보조로 한다.
- 반박
  - 리드
    - "상태"도 규칙에 넣는다. 기한 초과는 글자·작은 배지만 위험색으로 하고, 면 채움은 ①의 확인 버튼만 쓴다.
    - 홈 "지금" 선은 키 컬러로 한다(HOME-05).
    - SET-81은 색이 아니라 배치 문제다.
  - ux3
    - 캘린더 일정 삭제는 5초 되돌리기가 있으니 중립이 맞다.
    - 다만 그러면 토스트가 유일한 안전망이 된다.
- 재반박(ux2): 전부 받아들였다.
- **판정: 안 A + 상태 규칙.**
  - 위험색 = ① 되돌릴 수 없는 동작의 버튼, ② 기한 초과 상태의 글자·작은 배지.
  - 면 채움은 ①의 확인 버튼에만 쓴다.
  - 확정 해제 확인창은 중립 채움에 결과 한 줄("일지는 초안으로 돌아가고 내보낸 파일은 그대로예요")을 붙인다.
- 사유: 위험색은 드물게 쓸 때 신호가 된다(critique 휴리스틱 4·5). 되돌릴 수 있는 동작은 확인보다 되돌리기가 정석이다(WDG Destructive actions).
- 남은 이견(ux3, 작음): 일정 삭제의 안전망. 리드 답은 다음과 같다.
  - 토스트는 마우스·포커스가 올라가면 멈춘다.
  - 반복 일정 "이후 모두"는 범위 선택 창이 확인 역할을 한다.
  - 그래서 추가 확인은 두지 않는다. 토스트 길이 문제는 X-04에서 함께 다룬다.

## X-04 Esc·되돌리기 규칙 (COM-01·02, CAL-89, LOG-101, COM-32)
- 안(리드)
  - 안 A: Esc는 닫기·포커스 빼기만 하고 글은 남긴다.
  - 안 B: Esc 두 번에 비운다.
  - 안 C: 비우고 토스트를 띄운다.
  - 공통 규칙: 데이터를 바꾸는 동작은 5초 되돌리기 토스트를 띄운다. Ctrl+Z는 입력칸이 아닐 때 토스트로 연결한다.
- 반박
  - ux2
    - 일지 표에서 Ctrl+Z가 칸 글자 되돌리기인지 줄 삭제 되돌리기인지 모호하다.
    - 5초는 확정에 짧다. 확정 되돌리기는 안 D(완료 창 상시 [해제])로 한다.
  - ux3
    - 캘린더 대화창은 "닫기 = 버리기"라 안 A만으로는 같은 손실이 남는다.
    - 내용이 있으면 Esc·바깥 누르기를 한 번 막는다(안 D).
    - 토스트가 사라지면 Ctrl+Z도 끝난다는 점을 적는다.
- 재반박(리드): 셋 다 받아들이고 다음을 고쳤다.
  - 대화창 확인 조건은 "처음 값과 다름(dirty)"이다.
  - 확인은 겹친 모달이 아니라 창 안 한 줄로 한다. 포커스는 [계속 편집]에 둔다.
  - 바깥 누르기는 누름과 뗌이 모두 바깥일 때만 닫는다.
- **판정: 안 A + 공통 규칙(고친 문구) + 대화창 안 D.**
  1. Esc는 사용자가 쓴 글을 말없이 버리지 않는다.
     - 저장 단계가 없는 입력(빠른 입력·시트)에서는 Esc가 닫기·포커스 빼기만 한다. 비우기는 × 버튼으로 한다.
     - 저장 단계가 있는 창(일정 상세 등)은 변경이 있으면 창 안에서 한 번 묻는다.
  2. 데이터를 바꾸는 동작은 5초 되돌리기 토스트를 띄운다. 줄 삭제(LOG-101)와 타이머 정지(COM-32)도 대상이다.
  3. 되돌리기의 기준은 보이는 [되돌리기] 버튼이다. Ctrl+Z는 토스트가 떠 있고 포커스가 글 입력칸이 아닐 때만 연결한다. 빈 입력칸은 글 입력칸으로 보지 않는다. 토스트가 사라지면 Ctrl+Z도 끝난다.
  4. 결과가 문서 상태인 동작(일지 확정)은 토스트가 아니라 완료 창 안에 상시 [해제]를 둔다.
- 사유
  - critique 휴리스틱 3·5.
  - WDG "Warn before navigation with unsaved changes", "undo window".
  - Linear·Todoist·Slack 입력창에서도 Esc가 글을 지우지 않는다.
  - ux3 mock에서 대화창 Esc 손실을 재현했다(CAL-89).
- 남은 이견(ux2·ux3): 토스트 5초가 짧다는 우려가 있다.
  - 리드 판단은 5초 유지다. 하루 수십 번 뜨는 토스트가 길면 다음 토스트와 겹친다. 마우스·포커스로 멈출 수 있고, 문서 상태 동작은 4번 규칙으로 뺐다.
  - 운영 뒤 되돌리기 사용 로그로 다시 볼 것을 제안한다.
- 확인할 점: WY-frontend가 COM-01·02를 고쳤다(2026-10-12). 고친 동작이 위 1·3번과 같은지 재평가 때 확인한다. 화면정의서 SCR-COM-02 "Esc로 입력 비우기"는 개정해야 한다(WY-design).
