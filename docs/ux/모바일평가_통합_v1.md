## 요약

### 가장 큰 문제 5개 (영향 순)
1. **휴대폰 뒤로 가기가 창을 닫지 않는다(중간, UX-M-COM-02 + CAL-71).** 빠른 기록 시트·확인 대기 패널·일정 상세 시트 모두 같다. 앱 전체에 `popstate` 처리가 0곳이다(리드가 grep으로 다시 확인). 빠른 기록 시트에서는 앱을 떠나 쓰던 글이 사라지고(PWA), 일정 상세 시트는 뒤 화면만 바뀌고 시트가 남는다. 업무 상세는 주소(`/tasks/{id}`)를 가진 패널이라 뒤로 가기로 닫힌다(ux2 M10 통과) — 이것이 맞는 본보기다.
2. **홈 390에서 문서가 381px 더 스크롤되어 앱 틀이 위로 밀리고 빈 화면이 생긴다(중간, UX-M-COM-01).** 원인 하나(기준 상자 없는 `.srOnly` absolute)로 하루 여러 번 여는 홈이 깨져 보인다. 고치기 쉽다(`.content`에 `position: relative`).
3. **자정을 넘기면 하루 마감 길이 사라진다(중간, UX-M-HOME-03).** 띠는 "오늘 + 마감 시각 뒤"에만 뜬다. 야근하거나 잊은 사용자는 다음 날 홈에서 어제 마감 길을 찾지 못한다. 핵심 흐름 2단계의 입구 문제다.
4. **목록형 화면의 첫 화면이 크롬·쪼개진 글자에 먹힌다(중간, UX-M-TASK-43·CAL-70·CAL-72).** 업무 목록 위 크롬 300px(36%, 기준 30%), 캘린더 목록 보기 제목 36px 열에 5줄, 월 보기 아래 40% 빈 공간 + 일정 이름을 보려면 일 보기로 가야 함.
5. **390 전체 화면 패널이 대화창으로 알려지지 않는다(중간, UX-M-TASK-44).** 업무 상세가 `role="dialog"`·`inert` 없이 뒤 목록과 하단 탭을 Tab·낭독기 순서에 남긴다(WCAG 1.3.1·2.4.3). 가입 [회원가입]이 첫 화면 밖(AUTH-70)과 처리방침 표(AUTH-85 재확인)가 그다음이다.

### 잘된 점 3개 (유지할 것)
1. **시트 기본기.** 빠른 기록·기록 추가·하루 마감·통계 직접 선택·일정 상세 시트의 주 버튼이 모두 44px 높이로 엄지 영역(y 619~820)에 있고, 키보드 근사(390×500)에서도 입력칸과 함께 보인다. 입력 글자 16px, 390·360 전 화면 가로 넘침 0(세 세션 공통).
2. **되돌림이 완전한 하루 마감.** 홈 띠 → [다음] → [오늘 마감] 3번, 완료 시트의 [마감 취소] → [계속 두기]에 기본 포커스, 취소 뒤 바로 [다시 마감](ux2). 실수 비용이 낮다는 지난 평가의 장점이 모바일에서도 지켜졌다.
3. **상태 처리와 겹침 처리.** 오프라인 띠·시트 잠금·카드별 "연결되면 불러올게요"가 일관되고(리드·ux2), OS 다크에서도 `color-scheme`·`theme-color`가 맞으며, 캘린더 겹침은 일 보기 열 나눔·주 보기 "+4" 칩으로 읽힌다(ux3).
