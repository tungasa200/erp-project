## 4. 새 결함

### UX-COM-161 미인증 배너가 390·360에서 두 줄이다 (낮음)
- 화면: SCR-COM-07(홈·업무일지) · 390·360 · 축 1·7
- 측정
  - 390
    - 배너 358×60이다.
    - 문구 칸이 194px라 "인증하면 일지를 내보낼 수 / 있어요"로 접힌다(문구 칸 높이 42).
    - [인증하기] 72×44(x 238), ×44×44(x 322)다.
  - 360: 문구 칸 164px, 두 줄이다.
  - 증거: `docs/ux/evidence/r4c/home-390.png`
- 영향
  - 판단의 목적은 좁은 폭의 위쪽 크롬 줄이기였다. 높이가 60px로 이전과 같아 그 목적에 못 미친다.
  - 두 줄로 끊긴 "있어요"가 버튼과 따로 떠 보인다.
- 제안(WY-frontend, 문구를 바꾸려면 WY-design)
  - 문구 칸과 버튼 사이 여백, [인증하기] 좌우 패딩, × 영역을 줄여 390에서 한 줄을 확보한다. 버튼 높이 44는 유지한다.
  - 그래도 안 되면 "인증하면 내보낼 수 있어요"(약 180px)로 줄인다.
  - 360 한 줄은 문구를 줄여야 가능하다.
  - 목표: 390 이상은 배너 높이 44 + 위아래 여백.
- 근거: WY-design 판단 2026-10-12(COM-20) "360~767px … 한 줄"

### UX-COM-160 같은 등급 버튼의 굵기가 600과 800으로 갈린다 (낮음, 판단 필요)
- 화면: 공용 · 1280 · 축 5
- 측정(화면에 보이는 main 안 버튼·링크의 계산된 굵기)
  - 홈: 800은 [인증하기]·[했어요]·[수정]·[안 했어요]·[마감순]·[일지 보기]·[하루 마감]이다. 600은 [일 보기]·[업무 전체 보기]·[주간 일지]·[프로젝트]다.
  - 일지: [내보내기]·[확정]·[일지 확정]이 800, [입력]이 600이다.
  - 캘린더: [일정 만들기]가 800이다.
  - 설정 테마: [저장]이 800이다.
  - 업무: [마감순]이 800, 같은 줄 [프로젝트]·[상태]는 600이다.
- 문제
  - 토큰 주석(`--weight-title: 600 /* 제목·버튼 */`, `--weight-strong: 800 /* 숫자·배지 */`)과 판단 문장 "버튼·링크 600"과 어긋난다.
  - 이번 수정은 700·500·900만 옮겼다. 이전부터 800이던 버튼 규칙(`.yes`·`.no`·`.softButton`·`.secondaryLink`·`.bannerAction` 등)은 범위 밖이었다.
  - 업무 정렬 토글은 같은 줄의 두 칩이 800과 600으로 다르다.
- 영향
  - 같은 위계의 버튼이 굵기로 다른 중요도를 말한다. [일 보기] 600과 [일지 보기] 800은 홈에서 같은 카드 머리 링크다.
  - 숫자·배지를 강조하는 800의 뜻이 흐려진다.
- 제안
  - WY-design이 정한다. 하나는 "버튼 = 600"을 지키고 800 버튼 규칙을 600으로 옮기는 것이다. 다른 하나는 "주 동작 버튼만 800"을 규칙에 적는 것이다. 그 뒤 담당은 WY-frontend(공용·홈·일지·설정)와 WY-frontend2(캘린더)다.
  - 정렬 토글(`마감순`/`프로젝트`/`상태`)의 선택 표시는 굵기가 아니라 면으로 이미 구분되므로 600 하나로 맞춘다.
- 근거: 축 5(같은 의미는 같은 모양), 토큰 주석, 판단 2026-10-12 §5-3
