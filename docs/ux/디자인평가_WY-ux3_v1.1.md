## 3. 신규 지적

### UX-CAL-89 (일정 상세 창이 Esc·바깥 누름에 입력을 묻지 않고 버린다)
- 화면: SCR-CAL-02 일정 상세 · 폭/테마: 1280·390 기본 · 축: 3·4 · 심각도: 중간 · 구분: 구현 차이(+의도)
- 주 근거: impeccable critique 5번 오류 예방(Nielsen 5). 보조: web-design-guidelines "Forms: Warn before navigation with unsaved changes", `calendar/Modal.tsx:75`(overlay `onPointerDown`이 바로 `onClose`), `Modal.tsx:81-85`(Esc → 닫기).
- 문제: 제목·메모를 고친 뒤 Esc를 누르면 확인·초안 없이 창이 닫히고 수정은 사라진다(mock에서 제목을 바꾸고 Esc → 창 닫힘, 일정 제목 그대로, `UX-CAL-dialog-esc-1280.png`). 바깥 누름은 `pointerdown`이라 손가락이 살짝 닿기만 해도 닫힌다(스크롤하려다 배경을 짚는 경우).
- 영향: 긴 메모를 쓴 뒤 실수로 닫으면 복구 방법이 없다. 모바일에서 더 쉽게 일어난다.
- 제안: 수정이 있을 때만(제목·메모·시간 변경) Esc·바깥 누름에서 "저장 안 하고 닫을까요?"를 보이거나 초안을 남긴다. 빈 입력에서는 지금처럼 바로 닫는다.
- 근거: 소스 읽기+mock 재현 1회. 사용자 빈도는 낮지만 데이터 손실.
- 증거: `UX-CAL-dialog-esc-1280.png`, `frontend/src/calendar/Modal.tsx:75-85`.

### UX-CAL-93 (끌기 시각 문법: 옮길 자리가 "진행 중"과 같은 모양, 놓은 뒤 전이 없음)
- 화면: SCR-CAL-01·02 · 폭/테마: 1280 기본 · 축: 1·5 · 심각도: 낮음 · 구분: 의도 문제
- 주 근거: impeccable critique(시각 위계·의미 일관성). 보조: emil-design-eng "Spatial consistency / Preventing jarring changes", `calendar.module.css:407-410`(원본 `opacity .4`), `:443-454`(ghost `border: 2px solid`).
- 문제: 화면정의서 2.3은 계획=점선, 진행 중=실선이다. 끄는 동안 새 자리 표시(ghost)가 실선 테두리 + 그림자라 "지금 진행 중인 일정"과 같은 모양이다. 원본은 40% 투명으로 제자리에 남는다(`UX-CAL-drag-mid-1280.png`). 놓으면 블록이 순간 이동하고(전이 없음) 아래 토스트 "일정을 옮겼어요 [되돌리기]"만 남는다(`UX-CAL-drag-after-1280.png`).
- 영향: 사소함. 다만 점선의 뜻이 이미 헷갈린다는 쟁점(X-11)과 겹친다.
- 제안: ghost는 점선+그림자로 두거나 "옮기는 중" 전용 표시. 놓을 때는 전이 없이 즉시가 맞다(하루 수십 번 쓰는 동작, emil 빈도 표). 이 항목은 방향이 취향이라 심각도를 낮춤.
- 증거: `UX-CAL-drag-mid-1280.png`, `UX-CAL-drag-after-1280.png`.

### UX-CAL-94 (터치 끌기: 가장자리 자동 스크롤이 없다)
- 화면: SCR-CAL-02 일 보기 · 폭/테마: 390 · 축: 7·3 · 심각도: 중간 · 구분: 구현 차이(실기기 필요)
- 주 근거: impeccable audit 반응형("끌기가 스크롤을 삼키거나 끝까지 못 가는 경우"), critique 페르소나 Casey. 보조: emil-design-eng "Gesture and Drag Interactions: Damping/Friction at boundaries", web-design-guidelines "Drag … need tap/click and keyboard alternatives"(대안은 상세 창 시간 칸으로 있음 → 통과).
- 문제: 길게 눌러 잡은 뒤에는 `touchmove`를 막아 스크롤이 멈춘다(`touchHold.ts:34-37`). `TimeGrid.tsx`에는 끌기 중 `scrollBy`·가장자리 감지가 없다(grep 0건). 390에서 보이는 시간대는 약 8시간(v1 CAL-72)이라 09시 일정을 17시 이후로 옮기려면 화면 밖이다.
- 영향: 손가락으로는 보이는 구간 안에서만 옮길 수 있다. 우회: 상세 창에서 시간 입력(대안 존재).
- 제안: 끌기 중 가장자리 40px 안이면 자동 스크롤(속도는 거리 비례). 구현 비용은 중(TimeGrid + rAF).
- 근거: 소스 grep·`touchHold.ts`. **실기기 필요**: 실제 손가락 끌기·관성.
- 증거: 소스 `frontend/src/calendar/touchHold.ts:34-37`, `TimeGrid.tsx`(scroll 호출은 `:125`뿐).

### UX-CAL-95 (캘린더 요소에 호버·누름 피드백이 없고, 다른 곳의 호버는 터치 게이트가 없다)

### X-12 누름 피드백·진입 모션 — 동의(안 B) + 반박 1건(캘린더 끌기)
- 동의: 내 영역 transition이 settings 2곳뿐이고 `:active`가 1곳, `(hover: hover)`가 landing 2곳뿐이다. 캘린더는 hover가 2곳이라 **터치에서 hover가 남는 문제는 작다**.
- 반박·보완: **캘린더 끌기는 안 B의 "scale은 작은 원형 버튼만"에 걸리지 않는다.** 끌기·길게 누르기에는 안 B의 "모션 0"이 아니라 **잡힘 신호가 필요하다.** emil의 "하루 수십 번 쓰는 화면은 모션을 줄이라"는 권고는 전이(트랜지션)에 대한 것이고, **직접 조작의 응답(잡은 블록이 따라오고 그림자가 약간 생김)은 모션이 아니라 피드백이다.**
  - 현재: 길게 누르면 진동 10ms(`touchHold.ts`)만 있고 시각 신호가 없다(UX-CAL-hold-390.png: 450ms 뒤에도 블록 모양이 같다).
  - 규칙 문구: "직접 조작(끌기·길게 누르기·시트 끌기)의 응답은 0ms로 따라오고, 잡힘은 그림자 한 단계 + 불투명도 변화로 보인다. 놓을 때 되돌아가는 동작만 200ms."
- 점검: 끌기 중 `transform`만 쓰는지는 소스상 `left/top`으로 위치를 그리는 부분이 있어(TimeGrid.tsx `blockStyle`) 성능 점검 대상이다(CAL-95 참조, 값은 `미측정`).

### X-13 표기 규칙 — 동의(날짜 안 A, placeholder 안 B) + 건수 보탬
- 지시에 따라 지적(ID)이 아니라 판정 의견만 쓴다.
- 건수(내 영역, 소스): 끝에 "…"가 없는 placeholder, 손으로 만든 날짜 서식, 반 픽셀 글자 수를 위 집계에 적었다. 재량 정리 대상은 `calendar/time.ts`·`MiniCalendar.tsx` 날짜 표기, `QuickCreate.tsx` placeholder, 인증 폼 placeholder(`auth.module.css` 쪽은 라벨이 있어 영향 작음).

## 부록 C. 재반박

WY-ux2가 내 안 X-07·X-09·X-10에 남긴 반박 3건에 한 번씩 답한다.

### X-07 — 수용: 접어도 요약 한 줄과 기본값 기억을 둔다
- WY-ux2 의견("기록 N건 · 일지 확정/초안" 한 줄 요약을 접힘 막대에 남긴다, 기본 접힘 값을 사용자 설정으로 기억한다)을 **안 D에 넣는다.** 내 안의 안 D 문구를 다음과 같이 고친다.
  - 일 보기 업무 패널은 기본 접힘, **기록 패널은 접어도 머리글에 "기록 N건 · 일지 확정/초안" 요약 유지**.
  - 접힘 상태는 사용자 설정(기기 간 공유)에 기억한다. 기본값은 "접힘"이되, 한 번 펼친 사용자는 그 선택이 기억된다.
- 반대 의견 보존: WY-ux2는 "기록 패널은 아예 기본 펼침"이 낫다고 볼 수 있다(저장된 의견 없음). 위 요약 한 줄로 존재 인지 문제는 해소된다고 본다. 남는 차이는 "기본 접힘 vs 기본 펼침"이고, 겹침이 많은 날에는 접힘이 낫다는 것이 내 판단이다(측정: 일 1280 시간 열 122px → 약 400px).

### X-09 — 수용: 공백 채움 주의점을 구현 조건으로 명시
- WY-ux2의 지적이 맞다. 프리헤더 뒤에 공백 채움(`&zwnj;&nbsp;` 반복)이 없으면 일부 클라이언트가 본문 첫 줄(로고 "w worklog" → 코드)을 이어 붙인다. 구현 조건으로 **"숨김 프리헤더 + 공백 채움 40~100회 반복"을 한 묶음**으로 적는다.
- 확인은 Gmail 웹·모바일의 실제 미리보기가 필요한데 실메일 발송이 금지라 **`미측정`으로 유지한다.** 발송 승인(`WY-pm`)을 받은 뒤 사용자 본인 수신함에서 확인한다.

### X-10 — 부분 수용: 막대·accent-soft 대비를 재계산하고, 파생색은 값 조정 뒤에 다시 잰다
- 막대 대 카드 배경(비텍스트 3:1): `--color-accent` 대 흰 카드는 청록 3.65·초록 3.56·주황 3.35·파랑 4.4·빨강 4.4·분홍 4.5·보라 6.4·먹색 12.3이라 **전부 3:1을 넘는다.** 값 조정(안 A) 뒤에도 어두워지는 방향이라 같다. 막대 3:1은 문제가 아니다.
- accent-soft 위 accent-ink 글자: 재계산 결과 프리셋 8종 모두 4.5:1 이상이다. 다만 **accent-soft 대 카드 배경의 경계**는 1.03~1.1:1이라 X-02 보완과 같은 규칙(경계선 3:1 또는 윤곽 병용)이 필요하다.
- 요청: 프리셋 값을 조정(안 A)하면 `accent-soft`·`accent-softer`가 따라 바뀌므로 구현 직후 위 두 값을 다시 잰다. 지금 값 변경이 확정된 것은 아니라 **재계산은 조정 뒤 한 번**으로 한다.

### WY-ux(리드) 반박에 대한 한 번 답 — 전부 수용
- X-07: "+n"은 Tab으로 닿는 버튼(이름 "14시대 일정 3개 더"), 팝오버는 첫 항목 포커스·Esc로 복귀. 접힘 상태 기기 기억, 접힌 막대에 "업무 n · 기록 n건" 요약. 모두 안 A·D 구현 조건에 넣는다. (내 측정과 충돌 없음: 터치 "+n"은 44px 이상.)
- X-09: text/plain 첫 줄도 코드로 시작하지 않게 한다. 프리헤더·공백 채움 조건에 함께 적는다. 확인은 `미측정`(실메일 발송 금지) 유지.
- X-10: 이미 저장한 미달 색은 막지 않고 저장 때 경고 + 조정 값 제안에 동의(D-185 3:1 검사는 유지, 안 C 폐기). 대비 계약에 "어두운 토스트 위 포커스 링 2.39:1(COM-23)"과 accent-soft·통계 막대 3:1을 넣는다. 위 막대 3:1 계산(전 프리셋 통과)과 accent-soft 경계 규칙을 계약에 옮긴다. COM-98(theme-color)은 리드 COM-26과 하나로 묶는 데 동의.
