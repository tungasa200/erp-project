- **가장 큰 문제 (영향 순)**
  1. **UX-LOG-142 (중간):** 일지 줄을 지우고 0.8초 안에 다른 일지로 옮긴 뒤 토스트 [되돌리기]를 누르면, 아무 알림 없이 복원되지 않는다. 사용자는 되살렸다고 믿는다.
  2. **UX-LOG-143 (중간):** 업무 내용 칸은 비우고 결과만 쓴 실적 줄은 저장 대상에서 빠진다. 앱 안에서 다른 화면으로 가면 경고 없이 사라진다(LOG-140 수정에서 남은 경로).
  3. **UX-CAL-140 (중간):** 일정 창에서 고친 내용이 있을 때 Esc와 바깥 누르기는 확인 줄을 띄운다. 하지만 머리의 [×]는 묻지 않고 닫아 고친 내용이 사라진다(X-04 규칙 1).
  4. **UX-HOME-140 (중간):** 홈 첫 시야의 주인공이 여전히 흐리다.
     - "확인해 주세요" 노란 띠(992×47, 확인 대기 2건 이상이면 늘 보임)가 남아 있다.
     - 오늘 일정 [했어요]가 채움이다.
     - 확정 뒤에는 일지 카드 [내보내기]가 채움이다.
     - 확인 대기 수가 한 시야에 세 번 나온다. 목업 F1에는 채움도 노란 띠도 없다.
  5. **UX-SET-140 (중간):** 화면정의서 SCR-SET-02 ⑤ "하루 마감 시각" 칸이 설정 화면에 없다.
     - 알림 설정은 "설정 › 일반의 하루 마감 시각과 같아요 [18:00 ›]"로 일반 설정에 보낸다. 그런데 일반 설정에는 그 칸이 없다(막다른 길).
     - 마감 띠(X-02)와 마감 알림이 이 값을 따르므로, 사용자는 18:00에서 바꿀 수 없다.
- **잘된 점 (유지할 것)**
  1. **하루 마감이 짧고 안전해졌다.**
     - 띠 [하루 마감] → [모두 했어요] → [다음] → [마감하고 확정], 4클릭이다(규칙의 6→4와 같다).
     - 키보드로는 Enter·Enter·(이슈 입력)·Ctrl+Enter이고, 이슈 칸의 Enter는 확정하지 않는다.
     - 완료 창의 [확정 해제]는 [계속 두기]에 포커스를 두고, 해제 뒤에는 "초안으로 돌렸어요" + [다시 마감]·[일지 보기]가 된다.
     - 숙련자는 팔레트 "빠른 마감" 한 번이면 같은 완료 창에 닿는다.
  2. **일지가 글을 잃지 않는 쪽으로 단단해졌다.**
     - LOG-140: 빈 줄이 있어도 삭제가 저장되고 새로고침 뒤에도 유지된다.
     - LOG-141: 마지막 줄을 지우면 포커스가 [＋ 실적 줄 추가]로 간다.
     - LOG-49: 원본 바뀜 띠 → 확인 창 → "바뀐 기록으로 다시 확정했어요".
     - LOG-40: 오프라인 새로고침에서 서비스 워커로 셸이 뜨고, 오프라인 띠와 읽기 전용 입력이 그대로다.
  3. **빠른 입력의 안전망과 문법 피드백이 규칙대로다.**
     - [×]는 32×32이고 `::after` 44×44로 넓혔다. 누르면 입력칸으로 포커스가 돌아온다.
     - 잘못된 우선순위 `!5`에는 경고가 뜬다.
     - 없는 프로젝트는 "Enter를 누르면 새 프로젝트를 만들지 물어요" → Enter → 확인 칩으로 이어진다.
     - 팔레트는 제목이 정확히 같으면 그 업무를 먼저 둔다(COM-03).

### UX-COM-143 같은 입력 부품의 안내 문구가 화면마다 다르고 경고 조사가 틀렸다 (낮음)
- 화면: SCR-TASK-01, SCR-COM-02 · 축 5
- 사실
  - 업무 화면 [업무 추가] 입력의 placeholder가 예전 문구 "무엇을 하셨나요? 한 줄로 적어 보세요"다. 업무를 만드는 칸인데 과거형이고 물음표로 끝난다(HOME-12, X-13 placeholder 규칙).
  - 우선순위 경고가 "!5이 아니라"다. "5(오)"는 받침이 없으므로 "!5가 아니라"다. 기호 값이 숫자·글자 어느 쪽이든 맞게 하려면 "!5 대신 !높음·!보통·!낮음으로 적어요"로 조사를 피한다.
- 제안: 업무 화면은 "할 일을 한 줄로 적어 보세요"로 바꾼다. 경고 문구는 위처럼 바꾼다.
- 담당: WY-frontend

### UX-CAL-143 일 보기 [하루 마감] 링크가 48×24다 (낮음)
- 화면: SCR-CAL-02 · 1280·390 · 축 6·7
- 측정
  - [하루 마감]은 48×24이고 `::before`·`::after`가 없다.
  - 주 보기 "+n"은 24×28이고 `::after`가 24×44다. 높이는 44, 폭은 24다.
  - 둘 다 WCAG 2.5.8(24px)은 통과하고 기준표 44px에는 못 미친다.
- 제안: [하루 마감]은 `::after`로 위아래를 넓혀 44px로 한다(인증 화면 문장 안 링크와 같은 방식). "+n"은 폭도 44px로 넓히되 이웃 블록과 겹치지 않는지 함께 본다(보조 점검 #12).
- 담당: WY-frontend2

### UX-CAL-144 진행 중인 실선 블록도 낭독기에는 "계획 ·"으로 읽힌다 (낮음)

- 제안: 블록 이름의 접두를 화면의 상태 표시와 맞춘다(진행 중 / 했어요 / 계획). 눈으로 보는 정보와 낭독 정보가 같아야 한다(1.3.1).
- 담당: WY-frontend2(`calendar/TimeGrid.tsx:852`)
