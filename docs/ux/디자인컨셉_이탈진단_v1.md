# 디자인 컨셉 이탈 진단 v1 (앱 전체, 2026-10-13)

- 작성: WY-design. 계기: 사용자 의견 "업무 기록 툴 용도에 맞게 차분해지긴 했지만, 강조색과 일반색의 대비가 너무 약하고 앱 전반이 최초 디자인 컨셉과 너무 멀어졌다."
- 범위: 사용자 지시(2026-10-13)대로 목업은 홈만(`docs/ux/목업/홈PC_재디자인_목업_v1.html`) 만든다. 나머지 화면은 이 진단을 바탕으로 7장의 단계별 개선으로 조금씩 고친다.
- 비교 기준
  - 최초 컨셉: 화면정의서 2.1 C안 "친근한 플래너". 둥근 카드(20), 넉넉한 여백, **굵은 숫자로 현황을 먼저**, **프로젝트를 색으로 구분**.
  - 최초 목업: 화면 목업 캔버스(claude.ai artifact 5c4S5jtmx2yQtDFqMkF3CN)의 HOME-01, CAL-01, TASK-01, Sidebar.
  - 지금 앱: mock 모드 1280, 브랜치 feature/records-only 워킹트리(캘린더 미커밋 변경 포함).
- 측정 방법: 화면을 10px 격자로 짚어 그 점의 실제 바탕색을 셌다. 분류는 셋이다. 진한 색은 채도가 높고 흰 바탕 대비 3:1 이상인 면, 옅은 색은 채도가 조금 있는 면, 나머지는 무채색이다. 대비는 WCAG 상대 휘도로 계산했다.

## 1. 한 줄 결론

토큰 값은 처음과 거의 같다. `--color-accent` #4B3FD6과 파생 공식은 2026-10-04 이후 그대로다. 바뀐 것은 **강조를 어디에 싣느냐**다. D-212(X-02 "한 시야에 채움 하나", 상태는 글자색만)를 지키려고 진한 채움 대부분을 옅은 면(accent-soft·softer·faint)으로 내렸다. 그런데 이 옅은 면은 원래 "바탕 틴트"로 만든 단계라 흰 면 대비 1.08~1.21:1, 앱 바탕 대비 1.1:1이다. 그래서 **내려간 강조는 사실상 보이지 않는다.** 차분함은 위험색 제한과 버튼 수 줄이기에서 왔고, 컨셉을 지운 것은 "채움 → 안 보이는 옅은 면" 전환이다.

- 업무: [추가]가 채움이었고, 기한 칩은 초과가 빨강, 오늘이 노랑 옅은 면이었다.

- 업무 목록은 지금 강조가 하나도 없다.
- mock 캘린더에서는 계획 블록이 모두 키 색 보라 점선으로 보이고 프로젝트 색이 보이지 않는다. 확정(채움) 블록도 보이지 않는다. mock 데이터 탓인지 상태 표현 회귀인지는 WY-frontend2가 지금 고치는 캘린더 상태 표현 작업에서 함께 확인할 것이다.

## 4. 원인 정리

E1이 뿌리다. X-02의 방향 "채움은 하나, 나머지는 옅은 면"은 맞다. 다만 그 옅은 면 토큰(accent-soft 12%)은 원래 **바탕 틴트**용으로 정한 값이라, 강조를 실어 나르기에는 너무 옅다. 그래서 강조가 모두 사라졌다. E2·E6은 같은 원인이 메뉴와 칩에서 드러난 것이다. 따라서 규칙을 되돌리기보다 **옅은 강조 단계를 보이게 만드는 것**이 먼저다(7장 1단계, 규칙 변경 없음). 그다음 컨셉의 상징 요소(현재 메뉴, 주 버튼 촉감, 프로젝트 색)를 하나씩 되살린다.

## 5. 지켜야 할 것

- AA: 글자 4.5:1, 경계·막대 3:1. 키 색 프리셋 8색 모두에서 확인한다.
- 사용자 설정 키 색: 파생은 color-mix 공식이다. 공식을 바꾸면 테마 화면의 대비 검사(D-185, 3:1 저장 막기)도 새 값으로 다시 확인한다.
- 홈 목업 v1의 결정 3건(사용자 카드 20261013-1400)은 그대로 둔다.

## 6. 홈 목업 v1과의 관계

- 7장 1단계(accent-soft 진하게)는 앱 전체 토큰이다. 홈 목업 v1은 지금 토큰으로 그렸다. 홈 목업이 승인되면 1단계를 함께 적용하고, 승인 카드에 "옅은 강조 면이 이 정도 더 진해진다"는 점을 함께 보인다(아래 값).
- 결정 3(확정 = 옅은 면)은 차분함 쪽이다. 컨셉의 "프로젝트를 색으로"는 날짜 칸 프로젝트 색, 진행 중 실선, 확정 행 진한 ink 글자로 남긴다. 사용자가 캘린더의 색 존재감을 더 원하면, 캘린더만 확정을 base 채움으로 두는 대안이 있다(사용자 카드에서 함께 물을 수 있음).

## 7. 조금씩 개선: 단계 목록 (한 단계 = 커밋 하나)

우선순위는 강조 대비가 먼저다. **[전체 토큰]** 표시가 있는 단계는 앱 전체 토큰을 바꾸므로 홈 목업 승인 결과와 맞춰 적용한다.

### 1단계 [전체 토큰] 옅은 강조 단계를 보이게 (규칙 변경 없음)
- 바꿀 토큰(`frontend/src/theme/tokens.css`, 화면정의서 2.2 파생 토큰 표):
  - `--color-accent-soft`: 흰색 88% → **80%** 혼합(accent 20%). 기본 #E9E8FA → **#DBD9F7**.
  - `--color-accent-softer`: 흰색 92% → **88%**(accent 12%). #F1F0FC → **#E9E8FA**(지금 soft 값).
  - `--color-accent-faint`: 그대로(5%). 캘린더 오늘 열·업무 행처럼 넓은 면이라 진하게 하지 않는다.
- 기대 효과(기본 보라):
  - soft와 흰 면: 1.21 → 1.37. soft와 바탕: 1.10 → 1.25.
  - 선택 메뉴·[했어요]·하루 마감 띠·필터 칩·선택 탭이 "켜져 보인다".
  - 진한 채움 수는 그대로라 X-02는 지킨다.
- 대비 확인(계산): soft 20% 위 accent-ink 글자는 프리셋 8색 최저 4.94(주황), 보라 6.83으로 AA 통과. soft 위 글자는 accent가 아니라 반드시 accent-ink를 쓴다(accent 글자는 프리셋 7색에서 3.5:1로 미달).
- 화면: 코드 변경 없이 토큰만 바꾼다. 확인할 곳은 사이드바·홈·캘린더 머리·업무 필터·설정 테마 미리보기 1280/390, 그리고 프리셋 8색이다.
- 함께 고칠 것: 테마 화면(SCR-SET-04)에 직접 고른 색 검사로 "soft 위 ink 4.5:1"을 더한다(D-185 보강, 결정 필요 여부는 WY-pm 판단).
- 담당: WY-frontend(토큰). 규칙 변경 없음. 화면정의서 2.2 표 값은 개정대기에 올린다.

### 2단계 [전체 토큰과 무관] 현재 위치를 컨셉대로: 사이드바 현재 메뉴 (규칙 변경 필요)
- 안 A(추천, 컨셉 복원): 현재 메뉴는 accent 채움 + on-accent 글자·아이콘(최초 Sidebar 목업). X-02에 "내비게이션 현재 위치는 채움 수에 넣지 않는다" 예외를 더한다.
- 안 B(규칙 그대로): 1단계 soft 20% 면 + 아이콘만 accent. 바탕 대비는 1.25에 머문다.
- 기대 효과: 모든 화면에 "지금 어디"를 알려 주는 진한 점이 하나씩 생긴다. 컨셉의 키 색 존재감을 가장 적은 면적으로 돌려준다.
- 화면: AppShell 사이드바, 태블릿 레일, 모바일 하단 탭(하단 탭은 아이콘·글자 accent로만 하고 채움은 하지 않음).
- 담당: WY-frontend(AppShell.module.css). 규칙 변경: X-02 예외 1줄(사용자 결정).

    selected 면 위에서 accent-ink 글자는 주황 4.41로 미달한다. 그래서 글자는 ink-strong을 쓴다.
  - 직접 고른 색: `theme.ts menuTextContrast`를 이 짝으로 바꾼다. 지금은 ink 대 soft 12%로 계산하므로 ink-strong 대 selected 28%로 고친다. 4.5 미만이면 지금처럼 `darkenForWhite` 제안 색을 보인다. 예: 노랑 #FFD43B는 4.05로 제안 대상이다.
  - **고대비(forced-colors)**: 면이 지워지므로 현재 메뉴와 레일은 `background: Highlight; color: HighlightText`로 칠하고, 아이콘은 currentColor다. 하단 탭은 `color: Highlight`에 글자 밑줄 2px(offset 3px)을 더해, 색이 없어도 현재 탭을 알 수 있게 한다.
  - 상태는 지금처럼 `aria-current="page"`로 전한다. 색과 굵기는 눈으로 보는 보조다.
  - 화면정의서: 2.2 파생 토큰 표에 selected 한 줄을 더하고, SCR-COM-01 사이드바·레일·하단 탭 현재 항목 표현을 바꾼다. 개정대기_화면정의서에 올렸다.
