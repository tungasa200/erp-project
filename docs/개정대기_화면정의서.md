# 개정 대기 목록 (화면정의서·화면 목업)

다음 개정 때 화면정의서와 화면 목업 캔버스에 반영할 항목이다. 담당은 WY-design이다.

- 단계가 진행되는 동안에는 항목을 추가만 한다. 화면정의서는 화면 내용이 실제로 바뀔 때만, 단계가 끝날 때 모아 발행한다. 기준 문서 버전만 바뀐 것으로는 발행하지 않고 다음 화면 변경 때 함께 반영한다.
- 구현을 막는 화면 변경만 예외로 바로 발행하며, 이때도 WY-pm에 먼저 묻는다.
- 결정은 [결정기록.md](결정기록.md)에 D-nn으로 기록되며(WY-planner 담당), 여기에는 화면정의서·목업의 어느 곳을 고칠지만 적는다.
- 개정에 반영한 항목은 지운다.
- 항목 형식: `날짜 · 출처 · 관련 ID` 다음 줄에 반영 위치(문서·장·ID)와 내용.

  2.5의 "입력 오류는 해당 칸 아래에 표시한다…" 다음에 더한다: 제출(버튼·Enter) 때 오류가 있으면 화면 순서상 첫 오류 칸으로 포커스를 옮긴다. 칸은 aria-invalid와 aria-describedby(오류 문구)로 오류를 읽는다. 동의 묶음 오류면 체크하지 않은 첫 필수 항목으로. 서버가 돌려준 칸별 오류(errors[])도 같다. 화면에 없는 칸의 오류(토스트)·폼 위 띠(429 잠금 등, 띠로 포커스)는 지금 규칙 그대로. 입력하는 동안 바로 보이는 오류(72바이트 초과 등)는 포커스를 옮기지 않는다. 통계 직접 선택(SCR-STAT-01)이 이미 같은 동작이라 공통 규칙으로 올린다. SCR-AUTH-03 actions에 "가입 실패 시 첫 오류 칸으로 포커스(2.5)" 한 줄. 목업 변경 없음.
