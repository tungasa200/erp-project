R8 세션 활동 — 시각화 스케치 3안

같은 데이터(최근 40분)를 세 가지로 그렸습니다. 이야기: WY-qa가 결함을 보고 → WY-pm이 WY-frontend2에 배정 → 수정 → WY-commit 커밋 → WY-qa 재검증 통과. 동시에 WY-backend1은 권한 확인을 기다리고, WY-pm은 사용자 결정 카드를 기다립니다. 상태 표시는 세 안 모두 같습니다: 초록 회전 고리 = 일하는 중, 회색 고리 = 대기, 빨강 맥박 = 권한 확인 대기, 점선·흐림 = 멈춤.

노드를 누르면 이 세션의 최근 메시지가 펼쳐집니다

좋은 점

  • 누가 누구와 주고받는지, 어디가 막혔는지가 한눈에 보입니다.
  • 움직이는 점으로 ‘지금 오가는 중’이 바로 느껴집니다(패널 시절 감각에 가장 가까움).

아쉬운 점

  • 순서가 약합니다. 보고 → 수정 → 재검증의 차례는 숫자 배지로만 보입니다.
  • 세션이 10개를 넘으면 선이 엉킵니다. 좁은 사이드바에는 맞지 않습니다.
  • 노드 자리 잡기(배치 계산)를 따로 구현해야 합니다.

B. 스윔레인 — 세션마다 한 줄, 가로가 시간

좋은 점

  • 시간, 순서, 동시 진행, 상태 이력이 모두 보입니다. ‘언제부터 막혔나’가 띠 길이로 읽힙니다.
  • 결함 → 수정 → 재검증 묶음을 점선 테두리 하나로 감쌀 수 있습니다.

아쉬운 점

  • 가로 폭이 필요합니다. 사이드바에서는 세로로 돌리거나 다른 보기가 필요합니다.
  • 메시지가 몰리면 화살표가 촘촘해집니다(확대·축소 필요).
  • 구현이 가장 무겁습니다(시간축 스케일, 겹침 처리).
