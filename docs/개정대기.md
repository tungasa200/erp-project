# 개정 대기 목록 (요구사항정의서·작업계획서)

다음 개정 때 요구사항정의서·작업계획서에 반영할 항목이다. 담당은 WY-planner다.

- 단계가 진행되는 동안에는 항목을 추가만 한다. 두 문서는 단계가 끝날 때(P1 종료, P2 종료 …) 이 목록을 모아 개정한다 (D-54).
- 구현을 막는 요구사항·범위 변경만 예외로 바로 개정하며, 이때도 WY-pm에 먼저 묻는다.
- 결정은 먼저 [결정기록.md](결정기록.md)에 D-nn으로 기록하고, 여기에는 문서의 어느 곳을 고칠지만 적는다.
- 개정에 반영한 항목은 지운다.
- 항목 형식: `날짜 · 출처 · 관련 ID` 다음 줄에 반영 위치(문서·장·ID)와 내용.

## 대기 항목

(REL 항목은 요구사항정의서 v2.3·작업계획서 v2.5에 반영, 2026-10-12)

2026-10-12 · D-214(카드 20261012-2215) · LOG-01~17, EXP-01~04, P3-02~
- 요구사항정의서: LOG(업무일지)·EXP(내보내기) 장 머리에 "D-214로 사용자 화면에서 숨김(코드·API·데이터는 유지, 서류·결재 서비스로 옮길 예정)"을 적고, 각 요구사항에 숨김 표시(상태 열 또는 비고). 지우지 않는다.
- 요구사항정의서: LOG-13 하루 마감은 남는 기능으로 문구 조정 — 3단계 마지막 '일지 확정'을 화면 표기 '[오늘 마감]'으로, 안에서는 그날 일지 확정을 유지, 실시간 일지 미리보기(LOG-12)는 숨김.
- 요구사항정의서: 제품 소개·범위(1장)의 '일지가 써지는 도구' 표현을 업무 기록 도구로 고치고, 범위 밖에 "업무일지·결재는 별도 서비스" 한 줄. 통계의 '확정 일지' 수 표현은 '마감한 날'로(관련 요구사항 ID는 개정 때 확인).
- 작업계획서: 업무일지·내보내기 작업(P3-02~ 일지 관련 행)에 "D-214 숨김, 코드 유지" 비고, 숨김 작업(feature/records-only PR) 행 추가.

2026-10-12 · D-215(카드 20261012-2300) · LOG-13·14, AUTH-08, UX-04, 1.4 용어 정의
- 요구사항정의서: LOG-14에 "D-215: 넘긴 계획·이슈를 다시 보는 화면은 없음, 다음 단계 후보 '다음 하루 마감 2단계에 어제 넘긴 계획 보이기'" 비고. 계획 줄이 가득 차면 더 넘길 수 없다는 점도 적는다.
- 요구사항정의서: 프로필(이름·소속·직책) 입력 요구사항과 UX-04의 '첫 일지 생성 때 프로필 요청'에 D-215 숨김 표시(값은 보관). 1.4 '미인증 계정' 정의의 "일지 내보내기 전에 인증이 필요하다"를 "인증이 필요한 기능은 없다(가입 직후 인증 단계는 유지)"로.
- 요구사항정의서: AUTH-08(이메일 인증)에 재촉 안내(배너·설정 미인증 줄·가입 안내 문장) 숨김 표시. 인증 단계·화면·API는 유지.
- 요구사항정의서: 이용약관 요구사항(REL 쪽)에 약관 개정(내보내기 문장 수정, 시행일·개정 이력) 반영 사실을 적는다.
- 작업계획서: feature/records-only 작업 행에 ②③④ 범위를 더한다.
