**목표.** wy-ops 0.7.2 패치 뒤 이 PC(DESKTOP-MAAC34T)를 작업 전용 호스트로 둔다. 다른 PC(이하 접속 PC)에서는 클릭 한 번이나 명령 한 줄로 다음을 한다.

- 승인 센터 카드 처리, 세션 현황·활동 피드 보기
- 코드 확인·편집, 터미널
- 프론트 미리보기(vite 5173, gateway 8080)

**확인한 사실(2026-10-09, 이 PC).**

- 메모리 8GB. VS Code 원격 서버가 호스트에서 수백 MB를 더 쓴다. 호스트 앞의 VS Code 창은 닫아 상쇄한다.

## 3. 일상 흐름(목표 상태)

1. 접속 PC에서 바로가기를 누른다 → VS Code가 Remote-SSH로 `C:\projects\erp-project`를 연다. 승인 센터·세션 현황 탭이 호스트 쪽에서 뜬다.
2. pm과 대화: 원격 터미널에서 `claude attach <pm>`. 나올 때는 attach만 빠져나오고 세션은 계속 돈다. 노트북을 닫아도 pm은 호스트에서 일한다.
3. 카드 처리: 승인 센터 탭에서 결정 → 호스트의 decisions 파일 → 대상 세션(0.7.2 asyncRewake)이 이어서 진행.
4. 미리보기: VS Code 포트 탭에서 5173·8080 포워딩 → 접속 PC 브라우저 `localhost`.
5. 작업 끝: VS Code 창만 닫는다. 역할 세션은 호스트에서 계속 돈다.
6. 쓰지 않을 때: `ssh <별칭>`으로 절전 명령. 다시 쓸 때 매직 패킷으로 깨움(집 안은 노트북, 집 밖은 집에 둔 폰에 SSH로 들어가서, D-163) → 1번부터.
7. 재부팅 뒤: 자동 로그인 → `ssh <별칭>` → 역할 세션을 명령 한 줄로 띄움(V2에서 자동 시작을 정하면 생략).
8. 재인증: GitHub·Tailscale 로그인이 필요하면 호스트 터미널에 나온 코드·주소를 노트북 브라우저에서 처리.
9. 비상: VS Code가 안 붙으면 `ssh <별칭>` 한 줄 → `session.ps1 health`. 그래도 안 되면 호스트에 키보드·모니터를 꽂아 PC 앞에서 처리.

순서: 손으로 준비(4.1·4.2) → 실측(4.4) → 실측대로 패키지화(4.3) → 전환(4.5). 패키지는 실측에서 실제로 된 절차만 담는다. 키보드·모니터 제거는 실측 마지막(V10) 단계다.

### 4.1 호스트 준비(사용자 손, 관리자 PowerShell — 백그라운드 세션은 권한 창에 답할 수 없음)
| # | 작업 | 담당 |
|---|---|---|
| H1 | Tailscale 설치·로그인, 트레이 메뉴 Run unattended 켜기(Windows 서비스로 로그인 전 동작), 기기 이름 정하기(예: 별칭 `wy-host`) | 사용자 |
| H2 | Tailscale 관리 콘솔에서 이 기기만 키 만료 끄기(D-159), 계정 2단계 인증 확인 | 사용자(자동화 브라우저는 Google 로그인이 막혀 WY-browser 불가) |

| H4 | sshd 설정: 공개키 로그인만, 비밀번호 로그인 끄기. 이 계정이 관리자면 키는 `C:\ProgramData\ssh\administrators_authorized_keys`(권한 정리 포함) | 사용자 |

| H6 | 전원: `powercfg`로 AC 자동 대기(유휴 타이머) 끄기, 최대 절전·빠른 시작 끄기(`powercfg /h off`), 화면 끄기만 유지(D-163). 절전은 SSH 명령으로 수동으로만. Windows 업데이트 사용 시간 지정 | 사용자 |
| H7 | 자동 로그인 설정(D-159). 비밀번호를 평문 레지스트리 값(`DefaultPassword`)으로 두는 방식은 피하고, 암호화해 저장하는 방식(예: Sysinternals Autologon)을 쓴다 | 사용자 |
| H8 | 깨우기 설정(D-163): 랜카드(Realtek) 속성에서 Wake on Magic Packet 켜기·"매직 패킷으로만 깨우기", BIOS(ASRock B550M Pro4) 'PCIE Devices Power On' 켜기. 호스트 랜카드 MAC 주소 확인(저장소에 적지 않음) | 사용자 |

### 4.6 D 드라이브 작업용 분리(사용자 지시 2026-10-09)

> **확정(D-157, 2026-10-09): Q9 ②.** 작업 폴더·gradle/npm 캐시·Docker 디스크 이미지는 C(SSD)에 그대로 두고, 안 쓰는 것(`C:\projects\bak` 등, 지금 52.5MB)만 원격 호스트 구성 때 D로 옮긴다. 경로가 바뀌지 않으므로 아래 이동 대상·경로 표·R1~R6은 **D를 SSD로 바꿀 때 재검토용**으로 남긴다.

원격 호스트 구성 때 어차피 세션을 모두 다시 띄우므로 같은 시점에 한 번에 한다. 목적은 공간 확보가 아니라 C=시스템, D=작업으로 나누는 것이다. pm 측정(2026-10-09): C 사용 65.5GB / 여유 166.7GB, D 여유 931GB. erp-project 0.07GB, Docker 데이터 1.6GB, agent-browser 1.1GB, gradle 캐시 0.9GB, `~/.claude` 0.8GB, npm 전역 0.6GB, pipx 0.4GB.

**먼저 볼 사실(WY-planner 확인 2026-10-09).** C는 SATA SSD(SanDisk 250GB), **D는 7200rpm HDD(WD 1TB)**, 둘 다 NTFS. 작업 폴더와 캐시는 작은 파일을 많이 읽고 쓴다(node_modules, gradle 빌드·캐시, git, vite 감시, Docker의 PostgreSQL). HDD로 옮기면 gradle 빌드·vitest·`npm install`·Docker DB가 눈에 띄게 느려질 수 있다. 그래서 아래 Q9에서 "자주 쓰는 것은 C에 두고, 안 쓰는 것만 D로"를 추천한다. 이동을 고르면 R5에서 빌드·테스트 시간을 이동 전후로 잰다.

**옮길 수 있는 대상과 방법.**
| 대상 | 지금 | 옮기는 방법 | 비고 |
|---|---|---|---|
| 작업 폴더: erp-project, agentTeamPackage, worklog-secret | `C:\projects\` | 세션 모두 멈춘 뒤 `robocopy /E /COPY:DAT`로 복사 → 검증 → 원본 이름 바꿔 보관 → 확인 후 삭제 | 세 폴더는 함께 옮긴다(`wy-ops.json`의 `secretsDir`가 상대 경로 `../worklog-secret`) |
| 오래된 백업 `C:\projects\bak` | C | 그냥 이동 | HDD여도 문제없음(Q9 ②의 대상) |
| Docker Desktop 디스크 이미지 | 기본 위치 | Docker Desktop 설정 → Resources → Advanced → Disk image location | DB 볼륨이 HDD로 감 |
| gradle 캐시 | `~/.gradle` | 사용자 환경 변수 `GRADLE_USER_HOME` 지정, 옛 캐시는 지우고 다시 받음 | 새 터미널·세션부터 적용 |
| npm 캐시 | `%LOCALAPPDATA%\npm-cache` | `npm config set cache <D 경로>`(사용자 `.npmrc`) | |
| agent-browser 브라우저·프로필 | `~/.agent-browser`(browsers, erp-chrome) | 위치 지정 설정이 있는지 먼저 확인, 없으면 그대로 둠 | WY-browser 전용 Chrome(CDP 9222) 프로필 포함 — 로그인 상태가 풀릴 수 있음 |

**옮기지 않는 것.**
| 대상 | 이유 |
|---|---|
| `~/.claude`(설정·메모리·대화 기록·승인 파일) | Claude Code와 승인 센터·훅이 홈 폴더 기준 경로를 고정으로 쓴다. 크기도 작다 |
| `~/.wy-tools`(wy-ops 설치본) | 확장 stub·훅·설치 스크립트가 홈 폴더 기준으로 찾는다 |
| 프로그램 설치 폴더(Node, JDK, VS Code, Docker 프로그램, npm 전역, pipx) | PATH·레지스트리·업데이트 도구가 설치 위치에 묶여 있고, 옮겨도 얻는 게 없다 |

**경로에 묶인 것과 확인 방법.**
| 묶인 것 | 내용 | 이동 뒤 할 일·확인 |
|---|---|---|
| Claude Code 프로젝트 폴더 | 메모리·대화 기록이 `~/.claude/projects/<경로를 바꾼 이름>`에 있다(지금 `C--projects-erp-project`). 새 경로는 `D--projects-erp-project`가 된다 | `memory/` 폴더를 새 이름 폴더로 복사. 새 경로에서 띄운 세션이 메모리 목록을 싣는지 확인 |
| 작업 공간 신뢰 | `~/.claude.json`의 `projects`에 `C:/projects/erp-project`로 등록. 신뢰되지 않은 폴더에서는 `claude --bg`가 "Workspace not trusted"로 실패(운영도구 구현계획 1장 실험) | 새 경로에서 대화형으로 한 번 열어 신뢰 승인(사용자 손). 허용 도구 등 프로젝트별 설정도 다시 생김 |
| 역할 세션 resume | 대화 기록이 옛 프로젝트 폴더에 있고 `claude agents` 항목의 cwd가 옛 경로 | 이어 붙이지 않는다. 작업 경계에서 모두 멈추고 `claude rm`으로 항목 정리, 새 경로에서 역할 파일로 새로 띄움(CLAUDE.md 세션 교체 방식, 인수인계 없음). 옛 대화 기록은 보관만 |

| wy-ops 설정·훅·lock | `wy-ops.json` 상대 경로, 훅 명령은 `~/.wy-tools` 기준, lock에 절대 경로 없음(확인함) | `install.ps1 doctor`, `gen` 다시 실행해 차이 없음 확인 |
| 승인 센터 네임스페이스 | `approvals.namespace` = `erp-project`(이름, 경로 아님) | 고칠 것 없음. 카드 하나 올려 확인 |
| VS Code | 작업 영역 상태가 폴더 경로에 묶임(열린 탭·터미널 등) | 새 경로로 열면 새 상태로 시작. 원격 바로가기(2장) 경로를 새 경로로 |
| 사용자 전역 설정 | `~/.claude/settings.json` 자동 모드 규칙 문구에 `C:\projects\erp-project`가 적혀 있음 | 사용자 손으로 경로 갱신(세션은 설정 파일을 고치지 않음) |
| 문서·역할 원본·메모리에 적힌 경로 | `C:\projects\worklog-secret\secret.txt`: 역할 원본 WY-qa·WY-qa2, `pm-ops.project.md`, 메모리 `local-secrets-folder.md`. 문서: PC이전_체크리스트, 운영도구_설치·요구사항·구현계획·패키징계획, 진행현황, 이 문서 | 원본(`.claude/ops/…`) 고친 뒤 `install.ps1 gen`. 문서는 담당 세션이 고침, 이력 문서(구현계획 등)는 그대로. `grep -ri "c:\\projects"`로 남은 곳 확인 |
| 그 밖 | `~/.claude/projects/d--projects-agentTeamPackage` 폴더가 이미 있다(예전 D 경로 흔적으로 보임) | 이동 때 그 폴더의 메모리와 겹치는지 확인 |

**실제 이동 vs 정션.**
| | 실제 이동(경로가 `D:\projects\…`로 바뀜) | 정션(`mklink /J C:\projects D:\projects`, 경로 그대로) |
|---|---|---|
| 편함 | 위 표의 경로를 한 번 고쳐야 함 | 문서·설정·메모리 그대로 |
| 위험 | 고칠 곳을 빠뜨리면 그 기능만 실패(찾기 쉬움) | 도구마다 실경로를 따라가는지가 다르다. Node `realpath`를 쓰는 도구(vite 등)는 D 경로로, 다른 도구는 C 경로로 보아 같은 파일이 두 경로로 섞일 수 있다(vite 파일 감시·허용 경로, Claude Code 프로젝트 폴더 이름, VS Code 파일 중복 열림). 이런 문제는 드문드문 나서 찾기 어렵다 |
