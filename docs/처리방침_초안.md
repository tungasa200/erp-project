## 2. 보유 기간과 파기

1. 회원 정보와 서비스 이용 기록은 회원 탈퇴 때까지 보유하고, 탈퇴하면 지체 없이 파기합니다. 계정 정보는 실제로 삭제하며 이메일 주소도 남기지 않습니다. 업무 데이터는 탈퇴 후 보통 1분 안에, 늦어도 20분 안에 모두 파기합니다. 업무 데이터를 처리하는 서버가 멈춰 있었다면 다시 켜진 직후 파기합니다. <!-- D-176. 출처: backend/worklog-service/src/main/java/com/erp/worklog/user/UserSyncJobs.java — 탈퇴 알림(사용자 변경 피드)을 30초마다 가져와 바로 파기(worklog.feed.poll-interval 기본 30s), 탈퇴 직전 처리 중이던 요청이 쓴 데이터까지 지우려고 15분(REPURGE_AFTER, access 토큰 10분보다 길게) 뒤 한 번 더 파기하며 이 작업은 5분 주기(repurge-interval 기본 5m) → 최대 약 20분. 2. 데이터베이스는 매일 백업하고 백업본은 7일 이내에 자동 파기합니다. 이 기간 동안 탈퇴한 회원의 정보가 백업본에 남아 있을 수 있으며, 백업에서 복원하는 경우 탈퇴 기록을 다시 적용해 파기합니다.
3. 탈퇴 사실을 확인하기 위해 회원 번호(이메일 등 회원을 알아볼 수 있는 정보 없음)와 탈퇴 시각을 백업 보관 기간보다 오래 보관합니다.
4. 인증 코드는 유효 시간이 지나면 쓸 수 없고, 로그인 세션 정보는 만료되거나 로그아웃·비밀번호 변경 때 무효가 됩니다. 만료된 정보는 매시간 한 번(매시 17분, UTC 기준) 정리합니다. 로그인 세션 정보는 만료 시각이 지난 뒤 첫 정리 때, 인증 코드는 발급 24시간 뒤 첫 정리 때 삭제합니다. <!-- 출처: backend/identity-service/src/main/java/com/erp/identity/feed/CleanupJobs.java (cron 기본값 0 17 * * * *, zone UTC; refresh_tokens는 expires_at 기준, verification_codes는 created_at+24h — 만료 코드도 24시간 발송 한도 계산에 씀). 저장소 설정(application*.yml·infra/)에 identity.cleanup.cron 덮어쓰기 없음 — Railway identity 서비스에 환경변수 IDENTITY_CLEANUP_CRON 없음(사용자 확인, 카드 20261011-0255) — 코드 기본값으로 동작. 폐기됐지만 만료 전인 토큰은 재사용 탐지용으로 만료까지 남김 -->

## 4. 제3자 제공

운영자는 회원의 개인정보를 제3자에게 제공하지 않습니다. 법령에 따라 요구받는 경우는 예외입니다.

## 5. 회원의 권리와 행사 방법

회원은 언제든지 설정 화면에서 프로필을 확인·수정하고, 회원 탈퇴로 개인정보 처리 정지와 삭제를 요청할 수 있습니다. 그 밖의 요청은 7항의 연락처로 할 수 있습니다.

## 6. 안전성 확보 조치

- 모든 통신을 HTTPS로 암호화합니다.
- 비밀번호는 BCrypt로, 인증 코드와 로그인 세션 정보는 SHA-256 해시로 저장합니다.
- 로그인 토큰은 브라우저 스크립트가 읽을 수 없는 쿠키로만 주고받습니다.
- 회원은 자기 데이터만 조회할 수 있도록 서버에서 소유자를 확인합니다.
- 로그인과 인증 메일 요청 횟수를 제한합니다.

## 7. 쿠키

서비스는 로그인 유지를 위한 쿠키 2개(접근 토큰 10분, 갱신 토큰 14일)만 씁니다. 광고·분석 쿠키는 쓰지 않습니다. 브라우저에서 쿠키를 막으면 로그인할 수 없습니다.
